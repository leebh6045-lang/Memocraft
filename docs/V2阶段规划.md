# Memocraft V2 阶段规划

> 本文保留用于追溯当时的判断与阶段划分；**当前实施路线见 [V2 实施规划](V2实施规划.md)**，两者冲突时以实施规划为准。

> 本文是 V2 的实施路线与验收依据。产品行为仍以 [产品规格](产品规格.md) 为准，架构细节以 [架构与实施](架构与实施.md) 为准，改动流程遵循 [开发准则](开发准则.md)。
> 范围决定：V2 等于补完 [产品规格](产品规格.md) 已定义、首轮未交付的剩余范围，不新增规格外功能。当前已交付范围见 [首轮交付](首轮交付.md)。

## 1. 术语与范围

首轮交付完成了四模块中的首页与随手记，以及手记搜索、主题与专注模式。规格中其余部分（知识归纳、长期事务与动态、全对象搜索、回收站、完整备份恢复、可读导出）当时被明确列为剩余范围，本文把它们统称 **V2**。

图片能力已在 V1.5 交付（本地选择、粘贴、独立图集、单独命名、放大查看，以及随数据库一起备份恢复），见 [V1.5 交付](V1.5交付.md)；V2 不重复实现，也不再需要预留「附件只做结构准备」。

V2 不新增规格外功能。拖拽排序与图片压缩、嵌套归纳、手动排序、子任务与截止日期、多草稿管理、自动同步、完整修订历史、AI 与语义搜索仍然后置。

## 4. V2 路线图

每个阶段都可独立验收、独立真实使用，不要求一次做完。阶段顺序按依赖确定：关联与引用先于全对象搜索，可见性谓词集中在回收站阶段一次落地。

| 阶段 | 目标                         | 主要交付                                                                                                                                                           | 验收要点                                                                                                      |
| ---- | ---------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------ | ------------------------------------------------------------------------------------------------------------- |
| 1    | 归纳：集合、多重收录、编辑   | `003_*.sql` 引入 `topics`、`note_topics`；归纳领域规则与校验；列表与详情页；收录与移出；手记抽屉显示所属归纳                                                       | 验收场景 3：一条手记被两个归纳收录，改正文两处一致；移出或删除一个归纳不丢手记与另一处关联                    |
| 2    | 事务：概况、动态时间线、引用 | 新增迁移引入 `threads`、`thread_entries`、`entry_notes`、`thread_notes`、`entry_tags`；事务列表与详情；动态增删改与时间线排序；动态/事务级引用手记；归档与重新启用 | 验收场景 6、7：动态级与事务级引用均可反查且不重复；补录过去动态时间线正确；手记修改不覆写动态描述             |
| 3    | 全对象搜索与再次查看         | 搜索服务覆盖手记、归纳、事务、动态的规定字段；浮层按类型分组并显示上下文；搜索结果可在对应界面定位                                                                 | 验收场景 9：中文、英文大小写、emoji、换行、引号、代码块与普通符号正确保存与查找；归档可搜，草稿与回收站不参与 |
| 4    | 回收站：软删除、恢复与一致性 | 删除与恢复能力；回收站页面；删除前展示受影响的收录与引用位置；跨实体可见性谓词统一                                                                                 | 验收场景 8：事务恢复不误恢复此前已删除的动态；父事务在回收站时动态不可见也不可单独恢复                        |
| 5    | 完整备份、恢复与可读导出     | 备份包含一致性数据库快照、附件目录与版本校验清单；恢复前校验、暂停写入、先备份当前库再整体替换；启动检测未完成恢复；Markdown 可读导出                              | 验收场景 10：备份恢复到干净目录后正文、属性、关系、草稿一致；损坏或不兼容备份不覆盖现有库                     |
| 6    | 平台与发行决定               | 应用图标；Windows 安装包路径与验证安排；签名、公证与是否分发到他人的决定                                                                                           | 验收场景 11：同一核心样例在两平台安装包中跑通；无对应环境时如实标注未验证，不写成已完成                       |

### 4.1 阶段 1 细节：知识归纳

- 归纳平级、无嵌套；标题必填，说明选填；稳定 ID 标识，重命名不重写关联。
- 创建时或稍后收录手记，也可在归纳内创建手记并自动带上当前归纳关联；分类仍用同一套四类与默认值。
- 一条手记可被多个归纳收录；移出当前归纳不影响正文、其他关联与分类。
- 归纳内手记默认按手记创建时间倒序；首版不做手动排序。
- 允许同名标题；创建时提示已有同名项，通过返回候选让用户确认，不静默改名。
- 删除归纳不删除手记，也不需要改变手记分类；删除入口在阶段 4 接入回收站。

### 4.2 阶段 2 细节：长期事务与动态

- 事务有标题、说明、手动维护的当前概况与进行中/已归档状态；归档只影响默认列表，内容仍可搜索与查看，也可重新启用。
- 动态必属于一个事务，含发生时间、必填简短描述、可选 Markdown 正文、可选标签、可选引用手记，以及自动维护的创建/修改时间。
- 发生时间默认当前时间，允许补录与修改；时间线默认最近在前，可切换顺序，同时间按创建时间与 ID 稳定排序。
- 动态可独立写完整，无须额外创建手记；有可复用内容时在同一流程中创建或选择手记并引用，任一步失败不留下半套结果。
- 动态编辑不改写引用手记，手记编辑也不改写动态的历史描述。
- 事务详情同时显示概况、动态时间线与直接关联手记。手账视图仍然后置。

### 4.3 阶段 3 细节：全对象搜索

- 覆盖范围：手记正文/标题/标签；归纳标题/说明；事务标题/说明/当前概况；动态描述/正文/标签。
- 结果显示对象类型、摘要与所属事务等上下文，可直接打开；打开手记进抽屉，打开归纳/事务进详情，打开动态定位到所属事务。
- 空输入展示最近内容，按键分组命名必须准确，不无依据宣称「最近访问」。
- 归档事务可检索；草稿、回收站内容与被删除父事务的动态默认不参与。
- 首版仍是子串匹配，大小写不敏感限于英文字母；分词、拼音、同义词与语义搜索后置。

### 4.4 阶段 4 细节：回收站

- 手记、归纳、事务、动态均可软删除与恢复；不提供自动清空或永久删除。
- 删除手记前展示受影响的收录与引用位置并确认；关系保留，普通集合不显示已删除手记，引用端显示已移入回收站，不产生无提示断链。
- 删除事务时其动态随父事务隐藏并可随之恢复；此前单独删除的动态在恢复父事务时仍留在回收站。
- 删除动态不删除引用手记；父事务在回收站时先恢复父事务。
- 事务归档与进入回收站是两个独立操作。

### 4.5 阶段 5 细节：备份、恢复与导出

- V1.5 已固定备份格式：目录包 = 数据库快照 + `attachments/` + `backup.json` 清单（格式版本、模式版本、创建时间、每个附件的相对路径、字节数与 SHA-256）。V2 在此之上补用户入口与活动库替换，改动格式时同步升级格式版本。
- 备份先写临时目标，校验完整性后发布；不覆盖已有有效备份；不一致或失败不得标记成功。
- 恢复前校验快照完整性、外键、模式版本与包内路径，拒绝包内路径逃逸与过新的未知格式。
- 恢复步骤：暂停新编辑与新数据变更 → 处理待保存内容并排空写入队列 → 生成当前库的恢复前备份 → 整体替换活动数据 → 重新打开并校验。任一步失败都保留或可恢复原数据。
- 启动时检测未完成的恢复，不把半套数据当正常库打开；在副本上迁移旧版本并验证后才切换。
- 可读导出生成 Markdown 正文与关系元数据，文件名包含稳定 ID，处理 Windows 非法字符；不把仅正文导出称为完整备份。

## 5. 关键设计决策

详细取舍见 [V2 架构决定](decisions/002-V2架构决定.md)。以下为影响面最大的几条。

1. **存储层按聚合根拆分，仍由单个 worker 持有唯一连接。** V1.5 已按此方向拆出 `note-image-store.ts` 与 `backup.ts`：它们与 `NoteStore` 共用同一条连接，在 worker 内装配，`NoteStore` 保留连接的所有权。V2 沿用同一模式加入归纳、事务与动态的存储实现，不引入通用仓储框架。
2. **所有可编辑实体统一使用 `revision` 并发保护。** 归纳、事务、动态与手记一样在编辑时带 `expectedRevision`，复用「同内容重试视为成功、其他版本差异视为冲突」的语义，避免每个实体各写一套。
3. **回收站的可见性由明确谓词统一表达。** 动态可见要求自身与父事务均未删除；关联展示对已删除一端显示占位。这条规则只在一处实现，并在集成测试中覆盖恢复顺序与父事务边界。
4. **长任务的超时不能沿用固定 30 秒。** 含附件的备份与恢复可能超过当前请求超时；存储请求需要按操作类型设置超时，并在界面上表达「进行中」与「不可取消」的真实状态。
5. **用户选择的目标路径只能来自主进程对话框。** 备份与导出由主进程弹出保存对话框取得绝对路径，渲染端只接收用于显示的路径，不获得任意路径读写能力。
6. **新实体的编辑现场独立，不共用首页草稿槽位。** 首页草稿槽位仍固定为 1；动态编辑器与现有手记抽屉互不覆盖。若后续需要多草稿，再单独设计。
7. **搜索先做全对象子串匹配，不提前上 FTS。** 在真实数据量下测量查询计划与响应时间后再决定是否引入全文索引或分词，不假设开启 FTS5 就自动具备合适的中文分词。

## 6. 界面与交互增量

现有界面基准仍然有效，V2 需要在其上补充并同步维护 [界面与交互基准](界面与交互基准.md)：

- 归纳列表与详情、事务列表与详情、动态时间线的布局与空状态；新建归纳/事务的表单从首页次级入口打开。
- 收录选择器与引用选择器的共用交互：搜索现有手记、显示说明或创建时间帮助区分同名项。
- 搜索浮层的多类型结果分组、类型标识、上下文行与键盘导航。
- 回收站页面与删除确认对话框：需要新增确认对话框组件，展示受影响的关联位置。
- 备份、恢复与导出的进度、失败与「不可取消」反馈；恢复是高风险操作，确认文案必须说明影响范围。
- 外部链接的安全打开规则：当前 Markdown 预览禁用了链接，规格要求按明确规则处理外部链接；V2 需要决定协议白名单与打开方式，并新增对应能力。

## 8. 风险与限制

- **规模未知。** 当前一次加载全部手记、前端过滤，搜索上限 50 条。V2 需要依据真实数据量测量后决定分页或索引策略，不凭猜测优化。
- **单一编辑闸门。** 现有 `busy` 状态与切页前 `flushAll` 会让所有模块共用同一个保存闸门；新增编辑现场时需要重新审视，避免一个模块的保存失败阻塞整站导航。
- **状态文件与偏好。** 外观偏好目前只存在渲染进程的本地存储，窗口位置、最近访问等尚未持久化；V2 若要显示「最近访问」必须真正落盘，不能凭界面文案暗示。
- **恢复是唯一会替换活动数据的操作。** 失败路径的验证优先级高于新功能；没有实测过的恢复流程不能宣称可用。
- **平台声明。** 当前只有 macOS arm64 证据，Windows 需要独立构建与运行环境，不能在无证据时声明支持。
- **文档同步成本。** 本文、产品规格、架构与实施、界面与交互基准、项目结构在 V2 各阶段都会变化，每阶段结束需同步，避免再次出现文档与实现不一致。

## 9. 明确不做

- 自定义或重命名大分类、截止日期、提醒、子任务、待办勾选或额外的进度字段。
- 收件箱模块、无限画布、白板、多草稿管理、嵌套归纳、手动排序、动态手账视图、依赖图、自动生成当前概况。

- 自动同步、完整修订历史、自动备份调度、插件系统、AI 与语义搜索。
- 永久删除与自动清空回收站。
