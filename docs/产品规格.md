# Memocraft 产品规格 · v1

> 当前开发规范。项目已进入首轮桌面实现；本文的完整 v1 目标不等于全部已完成。实际范围与验证见 [首轮交付](首轮交付.md)。
> 公开文档入口见 [项目说明](../项目说明.md)，提交范围见 [仓库内容政策](仓库内容政策.md)。

## 1. 产品定位

项目名为 **Memocraft**，中文名为 **创忆工坊**。这是一个本地优先的个人知识库，用来记录学习与开发中的疑问、知识盲区、零散收获和长期事务，并支持整理、回顾、检索与复用。

首版为 Electron + Vue + TypeScript 桌面应用，面向 macOS 与 Windows。桌面应用能在两端运行，与两端数据自动同步是不同目标；自动同步后置。

开发阶段在应用左下角显示“内测中”。这是发行阶段标识，不代表已有公开安装包，也不虚构版本号；实际版本信息在工程建立后从统一的应用元数据读取。

成功判据是：能方便地开始记录；内容可靠保存并可恢复；能从关键词、归纳或事务经历重新找到内容；至少有真实问题经历“记录疑问、补充理解、联系实践、再次查看”的过程。不要求每日打卡，也不以每条手记必须在固定期限内被使用衡量成功。

## 2. 四个功能模块

| 模块     | 定位                                                 | 默认内容或动作                           |
| -------- | ---------------------------------------------------- | ---------------------------------------- |
| 首页     | 可直接开始记录的草稿画布，也提供创建归纳与事务的入口 | 恢复当前草稿或显示空编辑区，可立即输入   |
| 随手记   | 存放与管理每一条独立手记                             | 全部未进入回收站的手记                   |
| 知识归纳 | 围绕主题收录相关手记                                 | 归纳列表，进入后查看说明与所收录手记     |
| 长期事务 | 记录一件长期事情的经历、进展与决策                   | 进行中的事务，进入后查看概况与动态时间线 |

首页是正式功能模块，即使它不对应独立的知识实体。**不另设“收件箱”模块。** 随手记默认展示全部有效记录，可按“收获、待办、完成、杂项”筛选；四类按此顺序呈现，“全部”是独立的筛选重置入口，不是第五种分类。搜索、备份、回收站是辅助能力，不新增核心模块。

## 3. 核心术语与关系

| 名称 | 代码概念               | 含义                                                           |
| ---- | ---------------------- | -------------------------------------------------------------- |
| 草稿 | `NoteDraft`            | 尚未正式保存的编辑内容，用于恢复首页记录现场                   |
| 手记 | `Note`                 | 可独立存在的记录；可以是疑问、线索、草稿式想法、待办或完整经验 |
| 归纳 | `Topic`                | 围绕一个主题建立的集合，有标题、说明与收录关系                 |
| 事务 | `Thread`               | 长期推进的一件事，有概况、生命周期与动态                       |
| 动态 | `ThreadEntry`          | 某时发生的操作、进展、想法或决定，必须属于一个事务             |
| 收录 | 手记与归纳的关联       | 多对多，同一手记可被多个归纳收录                               |
| 引用 | 手记与动态或事务的关联 | 多对多，表明知识被哪个实践场景使用                             |

手记加入归纳、关联动态或事务后，仍在“随手记”中。各页面展示同一条内容，修改后各处可见，不创建副本。关联重复执行不产生重复记录。

动态是历史记录；事务的“当前概况”是用户维护的现状描述。首版不自动根据历史动态推算当前配置。事务的进行中/已归档状态与动态实体是不同概念，不再使用 `State` 命名动态。

## 4. 首页：草稿画布与创建入口

1. 启动进入首页；恢复上次草稿，没有草稿则显示可直接输入的空白编辑区。首版为单条手记编辑画布，不实现无限画布、自由拖拽或白板节点。
2. 首页提供“保存手记”“创建归纳”“创建事务”。后两者打开相应表单，取消或完成表单不丢失正在写的手记草稿。
3. 手记只需输入正文并使用一个大分类；分类预选“收获”，可直接保存，无需额外勾选待办或完成。标题、标签、关联均可跳过。正文为空或纯空白时不能保存为正式手记。
4. 非空草稿自动持久化，显示保存中、已保存或失败状态。清空草稿也须持久化为清除操作，避免重启后旧内容重新出现。草稿不参与手记列表、数量、关联与全局搜索。编辑期间可能有尚未落盘的字符，界面不得提前声称已保存。
5. 切换模块前保存最新草稿；失败时保留内容，提供重试或取消导航。正常关闭时完成待保存工作，失败时明确提示；异常终止后恢复最后一次成功持久化的草稿。
6. 正式保存成功后，手记立即出现在随手记列表，首页准备下一条记录。手记创建与对应草稿清理必须一起提交；失败保留草稿。连续点击或重试不得重复创建。
7. 打开已有手记编辑时更新原记录，不默认复制新手记；保存失败保留编辑内容并提示。已有手记的编辑现场与首页新建草稿隔离，不能覆盖或清除首页草稿，返回首页仍能恢复原草稿。

“快速记录”衡量打开应用到可输入的便利程度，以及保存是否存在多余步骤；不要求长正文也在五秒内写完。

## 5. 随手记：全部独立记录

### 5.1 内容与属性

| 属性 | 规则                                                         |
| ---- | ------------------------------------------------------------ |
| 正文 | 必填，以 Markdown 文本保存，支持中文、换行、代码块与链接     |
| 标题 | 选填；未填写时展示正文首个非空行的截断摘要，不修改正文       |
| 分类 | 每条恰有一个，固定顺序为收获、待办、完成、杂项；新建预选收获 |
| 标签 | 选填，零到多个自由标签，可跨记录筛选                         |
| 图片 | 零到多张本地图片，作为手记的独立图集，见 5.3                 |
| 关联 | 零到多个归纳、事务或动态                                     |
| 时间 | 自动维护创建时间与修改时间                                   |

四类使用统一显示名称“收获、待办、完成、杂项”，其中“完成”承载已完成事项。首版不提供大分类的自定义、重命名、停用或排序；自由标签仍可描述主题、用途与形式。分类与标签各有用途，标签不会自动改变分类。

创建与编辑手记时只使用一组单选分类，不再提供“设为待办”开关、完成勾选或额外的任务状态表单。默认选中“收获”，减少快速记录时的操作；用户也可直接新建“完成”类记录，无需先建立待办。标题、标签和关联仍可在补充区域按需填写。

待办事项做完后，把分类由“待办”改为“完成”；需要继续处理时可改回“待办”。四类之间均可改选，修改后更新修改时间，不改变正文、创建时间或关联。完成与否只由当前分类表达，不保存第二份任务状态。不设置整理进度、问题进度、回顾标记或已取消状态。

### 5.2 列表与处理行为

- 默认展示全部有效手记，以手帐式卡片列表作为基础方向；默认按创建时间倒序，编辑不改变创建时间。
- 分类筛选按“收获、待办、完成、杂项”排列，提供独立“全部”入口；也支持标签、归纳筛选。选择某类后只显示该类有效手记，空结果明确显示，不能悄悄退回全部。
- 加入归纳、关联事务、补充解释和回顾内容都是普通使用动作，不要求另外维护处理进度。
- 支持补充正文与改选分类。分类变更立即反映在筛选和各处展示中；“完成”类仍属于全部手记，不因完成自动归档或删除。
- 详情显示所有有效归纳及事务/动态引用位置，可以跳转查看实践背景。
- 用户 Markdown 渲染需安全处理，不能执行正文中的脚本。

### 5.3 手记图片

图片是手记的独立图集，不嵌入 Markdown 正文，也不要求用户在正文里写引用语法。

- 入口：首页草稿与手记详情都提供「添加图片」（系统文件选择，可多选）与直接粘贴剪贴板图片两种方式；草稿里的图片在保存之前就能命名、放大查看与移出。
- 归属：一张图片属于且仅属于一条手记。保存手记之前，图片先归属首页草稿；保存时在同一事务里转成这条手记的图片，新草稿上不会留着刚保存过的图。图片在添加那一刻就写入数据目录、不在内存里暂存，异常退出后仍能恢复。
- 命名：每张图片有独立显示名称，可为空；为空时展示原文件名，再为空时按序号展示，不写回数据库。
- 查看：缩略图可点击放大查看（首页草稿、手记详情与归纳连读共用同一套放大层），放大层支持上一张/下一张与键盘关闭，关闭后焦点回到触发的缩略图。
- 排序：按加入顺序展示，首版不做手动排序，也不支持跨手记复用同一文件。
- 列表呈现：随手记的阅读流与归纳详情的连读会露出前几张附图缩略图，只读元数据、不复制文件；缩略图读不到时留占位，不影响正文与其他内容。
- 删除：图片采用软删除，文件保留；不提供物理删除与自动清理。
- 限制：单张不超过 20 MB，单条手记不超过 50 张且累计不超过 200 MB；超限明确拒绝并保留已添加的图片。仅接受可解码的 PNG、JPEG、GIF 与 WebP，类型按文件签名判定。
- 图片名称不参与搜索；首版不提供图片搜索、压缩、格式转换与 OCR。

## 6. 知识归纳

- 标题必填，说明选填。首版归纳平级，不提供嵌套。
- 创建时或稍后收录已有手记，也可在归纳内创建手记并自动带上当前归纳关联。分类仍使用同一套四类与默认值。
- 一条手记可以被多个归纳收录；移出当前归纳不影响正文、其他关联或手记分类。
- 归纳中展示说明与收录的手记，默认按手记创建时间倒序；可切换「最早在前」从头读一遍，选择保存在本机。首版不做手动排序。收录时间会被记录，但不作为排序依据。
- 归纳详情提供两种呈现：**连读**（默认，把收录的手记连成一篇文档，带本页目录与「打开 / 移出」）与**网格**（两列卡片）；呈现方式与顺序都存在本机，重启后保持。
- 稳定 ID 标识归纳，重命名不重写关联。允许同名标题，创建时提示已有同名项，关联选择时展示说明或创建时间帮助区分。
- 删除归纳进入回收站。其关联暂不在普通页面展示，手记继续存在；恢复后原收录关系恢复。

## 7. 长期事务与动态

### 7.1 事务

事务标题必填，说明与当前概况选填；支持进行中/已归档。归档只影响默认列表，内容仍可搜索和查看，也可重新启用。标题按稳定 ID 标识，同名处理与归纳一致。

事务详情显示概况、动态时间线和直接关联手记。直接关联用于整个事务的参考资料，不要求虚构一条动态来放置它。

### 7.2 动态

动态包含：发生时间、必填的简短描述、可选 Markdown 详细内容、可选标签、可选引用手记，以及自动记录的创建/修改时间。

- 每条动态必须属于一个事务，使用全局稳定 ID；首版不提供跨事务移动动态。
- 发生时间默认当前时间，允许补录与修改；时间线默认最近在前，可切换顺序，同时间以创建时间及 ID 稳定排序。
- 动态可以独立写完整，无须额外创建手记。有值得复用的内容时，可在同一流程中创建手记并引用，也可选择已有手记；任一步失败不留下半套结果。
- 动态编辑不会自动改写引用手记，手记编辑也不改写动态的历史描述。
- 引用指向手记当前版本。需要保留当时的配置或结论时写入动态正文；首版不提供手记历史版本快照。
- 时间线与手帐视图共享同一份动态数据；先完成时间线，手帐视图作为后续展示增强。

## 8. 搜索与再次查看

全局搜索覆盖手记正文/标题/标签、归纳标题/说明、事务标题/说明/当前概况、动态描述/正文/标签。首页草稿不参与搜索。

首版支持子串关键词检索与标签筛选，中文原文能命中；英文按约定忽略大小写，搜索符号作为文本处理。结果显示对象类型、摘要及所属事务等上下文，可直接打开。归档事务可检索，回收站内容默认不参与。

空结果明确说明没有匹配项，并提供查看全部或最近内容的入口。高级中文分词、拼音、同义词和语义搜索后置。通过搜索、归纳或事务时间线再次查看内容；不设置专门的回顾标记、复习调度、通知或打卡。

### 8.1 AI 接入扩展

设置页提供 DeepSeek 配置，支持 V4.1 Flash（默认）与 V4 Pro、保存/更换/清除 API Key 和连接测试。API 地址默认官方 `https://api.deepseek.com`，允许填写兼容服务的 Base URL（支持 `/v1` 子路径与完整接口地址归一化）、保存或恢复官方；留空保存恢复官方。所有 AI 功能使用已保存地址，未保存改动不能测试，保存失败保留输入与原配置。模型选择后自动保存；密钥成功保存后清空输入，不回读到页面。连接测试发送固定文字，实际生成成功后显示所选模型与耗时，会产生少量费用，不发送个人手记。地址与模型随知识库备份恢复，密钥仍独立加密；具体见 [自定义地址设计](features/ai/2026-10-AI自定义地址-设计.md)。

密钥由主进程使用系统保护加密，单独存于知识库目录之外，不进入知识库备份或 Markdown 导出；恢复知识库保留本机密钥。模型配置保存在 SQLite，随知识库备份恢复。系统保护或外部调用不可用时只影响 AI，其他本地功能继续使用。

首页草稿提供主动「AI 建议」：展示标签与现有归纳建议，标签由用户点击加入草稿，归纳只跳转详情、不自动收录。正文变化时标记旧建议；切页、保存手记或关闭卡片清理建议，关闭与恢复等待在途请求结束。建议结果不持久化，也不进入备份、导出或搜索。发送正文前 800 字符、标题与受限候选及标签参考；Flash 模型同时按图集加入顺序纳入最多 4 张草稿图片，累计 base64 不超过 8 MiB。Pro 模型不发送图片并提示切换 Flash，不自动换模型。超预算、超尺寸或不可读的图片跳过并提示数量；图片增删后旧建议标为过期。不发送其他手记正文、其他手记图片或归纳说明。

全局搜索面板的搜索词达到 4 字符时提供 AI 问答，600 ms 防抖；只检索当前有效手记文字，不含草稿、回收站、归纳、事务与动态。摘要可在同一面板展开，来源编号由本地映射为真实手记 ID 与标题，点击来源打开详情。未配置密钥时完全隐藏 AI 行；无命中时明确提示且不调用模型。问答只发送搜索词与最多 8 条手记的标题、分类和 300 字符命中摘录，不发送图片；结果只保留在本次搜索现场，手记变化或关闭面板后清空缓存，不修改手记。

「回顾」作为辅助入口放在四个主模块下方，按自然周或自然月自动生成主题概要与最多 5 条建议。周期按本机日历、查询按 UTC 半开区间；只使用本期有效手记及本地事实统计，最多 20 条摘录（每条 200 字符，超量时每类最多 5 条），Flash 可使用每条首图、全期最多 4 张及 8 MiB base64；Pro 仅使用文字。未配置优先引导到设置，空期不调用模型。结果缓存到 SQLite 并随整库备份恢复，手记变化不自动使缓存失效；重新生成失败保留旧结果，切页返回保持现场，整库恢复清理旧库现场。

归纳建议已由用户手测确认完成，范围与实际验证见 [阶段二交付](features/ai/2026-10-AI归纳建议-交付.md)。搜索问答见 [阶段三任务书](features/ai/2026-10-AI搜索问答-任务书.md)、[设计](features/ai/2026-10-AI搜索问答-设计.md) 和 [交付](features/ai/2026-10-AI搜索问答-交付.md)；周期总结依据 [阶段四任务书](features/ai/2026-10-AI周期总结-任务书.md)、[设计](features/ai/2026-10-AI周期总结-设计.md) 与 [交付](features/ai/2026-10-AI周期总结-交付.md)。AI 属于辅助扩展，不改变四个核心模块和现有分类规则。

## 9. 数据保护、删除与迁移

### 9.1 回收站

首版删除采用软删除；手记、归纳、事务和动态可恢复，不提供自动清空或永久删除。

- 删除手记时展示受影响的收录与引用位置并确认。关系保留；普通集合不显示已删除手记，动态/事务的引用位置显示已移入回收站的提示，不产生无提示断链。恢复后关联恢复。
- 删除归纳不删除手记，不改变手记分类。
- 删除事务时，其动态随父事务隐藏并可随之恢复，引用手记继续存在，其他事务不受影响。此前单独删除的动态在恢复父事务时仍留在回收站。
- 删除动态不删除其引用手记。若父事务仍在回收站，先恢复父事务再恢复动态。
- 事务归档和进入回收站是两个独立操作。

### 9.2 存储与备份

SQLite 是唯一结构化主存储，正文是库中的 Markdown 文本。图片存放在数据目录下的 `attachments/`，数据库只保存相对路径、类型、尺寸与显示名称，不保存机器绝对路径。

一旦存在受管理附件，备份恢复必须覆盖它们：V1.5 已实现「数据库快照 + 附件目录 + 校验清单」的一致备份目录包，以及恢复到干净目录；活动库替换式恢复、压缩包与增量备份属于 v1 后续范围。可读导出包含 Markdown 内容与关系元数据，不能将仅正文导出称为完整备份。

恢复前检查包完整性与版本兼容性。用户确认后，暂停新编辑与新的数据变更，处理待保存内容，再生成当前库的恢复前备份；保存或备份失败则停止恢复。恢复采用整体替换，不实现合并两份库；失败必须保留或能够恢复原数据，应用不能误打开半恢复的数据目录。需用真实样例实际验证恢复。

数据库放在应用数据目录，升级应用不得覆盖用户库。格式升级通过版本化迁移执行。备份可另存到其他磁盘或独立保存位置，代码 Git 仓库不承担用户数据备份。

核心验收场景：

1. 首页只输入正文，使用预选的“收获”即可保存；全部列表可见，空白正文被拒绝。
2. 切换模块、正常重启后草稿恢复；保存失败保留内容；连续点击保存只生成一条手记。
3. 同一手记被两个归纳收录，编辑正文后两处一致；移出或删除一个归纳不丢失手记和另一处关联。
4. 创建、编辑和筛选中的分类名称与顺序一致，每条手记只有一个分类；不出现待办或完成复选框。草稿恢复保留已选分类，是否被归纳收录不影响全部列表中的可见性。
5. 四类都能直接创建；待办改为完成及改回待办后筛选结果更新，正文与关联保持。全部视图包含四类；分类空结果可见，不回退为其他分类。
6. 动态级和事务级引用均可从手记反查；重复关联无重复项。
7. 补录过去动态后时间线正确；手记修改不会覆写动态正文中的历史描述。
8. 删除及恢复符合第 9 章规则；事务恢复不误恢复此前已删除的动态。
9. 中文、英文大小写、emoji、换行、引号、代码块及普通搜索符号正确保存与查找；归档内容可搜，草稿和回收站默认不搜。
10. 完整备份恢复到干净目录后，正文、属性、关系、草稿和已有附件一致；损坏或不兼容备份不会覆盖现有库。
11. 同一核心样例在 macOS 和 Windows 安装包中跑通，数据库驱动与数据路径经实际验证。
12. 开发阶段应用左下角显示“内测中”，模块切换不改变该标识，不展示虚构发布版本。

业务规则采用自动化测试，桌面关键路径采用界面测试和手工验证，真实使用用于判断便利程度。工具与实施里程碑见配套文档。
