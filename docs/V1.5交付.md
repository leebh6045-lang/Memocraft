# V1.5 交付 · 手记图片 · 2026-09-22

## 本轮成果

在首轮交付的基础上加入手记图片能力，并把附件纳入备份范围。图片是手记的独立图集，不嵌入 Markdown 正文。

已实现：手记详情内的「添加图片」系统文件选择（可多选）、直接粘贴剪贴板图片、缩略图网格、每张图片的独立命名、点击放大查看（上一张/下一张、Esc 关闭、焦点回到触发缩略图）、二次确认移出；图片按文件签名判定真实类型，按 `deleted_at` 软删除；备份为「数据库快照 + 附件目录 + SHA-256 校验清单」的目录包，恢复支持目录包与早期的裸数据库快照。

首页草稿阶段不提供图片入口：图片必须挂在已存在的手记上，界面明确提示「先保存这条手记，再加入图片」，不写入无法归属的图片，也不把用户刚选的图暂存在内存里等提交。

## 关键文件

- `migrations/002_note_images.sql`：图片表，含路径 CHECK、外键、位置唯一约束。
- `src/domain/note-image.ts`：图片类型、限制常量、文件签名识别、宽高解析、显示名称回退。
- `src/storage/note-image-store.ts`：文件落盘与元数据事务、补偿删除、按 ID 取图、备份导出。
- `src/storage/backup.ts`：备份目录包、清单校验、恢复到干净目录。
- `src/main/image-protocol.ts`：`memocraft-image://` 协议登记与处理。
- `src/renderer/src/components/NoteImageGallery.vue`、`composables/useNoteImages.ts`：图集界面与现场。

设计与取舍见 [V1.5 图片设计](V1.5图片设计.md)。

## 期间修正的实际缺陷

以下都是本轮实测暴露、已修复的问题，记录以备复核：

1. 图片协议最初按 `initiatorOrigin` 判定来源，导致渲染进程的图片请求全部 403。实测该页面来源是 `file://`；改为只接受 `file:`、`'null'` 与缺失三种情况后又发现会误伤开发模式（界面来自 `http://localhost`），最终去掉来源白名单——访问控制由按图片 ID 的存储层校验承担，协议本身只注册在本窗口会话上。
2. 首版 PNG 测试样例只有文件头合法、CRC 与 zlib 数据不合法，浏览器能读出宽高却无法解码。已改为真正可解码的最小 PNG，并让桌面测试断言像素加载成功，避免再次用「头部合法」冒充「图片可用」。
3. 关闭放大层原本只清空「最后打开」标记而没有关闭浮层，且重命名会重建缩略图节点使焦点落空。现在关闭与焦点回位走同一条路径，并按图片 ID 重新定位缩略图。
4. 新增图片的位置原本取「可见图片数量」，软删除后与既有位置冲突。改为取 `max(position) + 1`。
5. 集成测试原先把「复制主库文件」当作一致快照，实际会漏掉 WAL 中尚未合并的内容；已改用 SQLite 备份接口。

## 剩余限制

- 备份仍是目录包，不含压缩、增量与保留策略；**活动库替换式恢复未实现**，恢复只能写入干净目录。
- 没有自动清理孤儿文件：文件写入成功但数据库插行失败且补偿删除也失败时，会留下不可见的文件；备份会一并复制。处理策略留待回收站阶段评估。
- 拖拽文件进入编辑器未实现；图片不能跨手记复用、不能嵌入正文、不能排序。
- 回收站界面、归纳、事务、全对象搜索、可读导出仍未实现，按 [V2 阶段规划](V2阶段规划.md) 推进。
- 应用仍为默认 Electron 图标、无签名与公证；Windows 未验证。
