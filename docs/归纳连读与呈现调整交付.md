# 归纳连读与呈现调整交付 · 2026-09-28

## 交付内容

在已交付的「随手记呈现方式 + 归纳目录」基础上做五处调整，并把一处归纳内的卡片缺陷修掉。改动集中在渲染端；唯一的跨层改动是新增只读的图片摘要批量接口（供列表缩略图使用），**不涉及数据库迁移、不改变既有数据结构**。

### 1. 归纳内卡片形变（缺陷修复）

- 现象：归纳详情里收录的手记一多，同一行的卡片宽高不齐，标签上下错开，「移出」按钮还会浮到卡片外面。
- 原因：网格只拉伸外层 `.topic-note`，里面的卡片是 `<button class="card">`，默认按内容收缩，于是宽高都不等于格子。
- 修法：`.topic-note > .card` 显式 `width/height: 100%`；`.card-foot` 改为 `margin-top: auto` + `padding-top: 4px`，标签行贴住卡片底部，同一行对齐。
- 顺带：新增 `noteExcerpt()`，没填标题时摘要跳过被当作标题的正文首行（此前同一句话在卡片上出现两次）。网格卡片、阅读流卡片、连读小节共用这一条规则。

### 2. 随手记工具栏

- 呈现设置整组靠右：左侧只留标签筛选，右侧依次是**分段方式下拉框**与**呈现方式**（网格 · 阅读流 · 按时间），窄窗换行后这一组仍靠右。
- 去掉阅读流的「按时间分段」勾选框：**阅读流固定按时间分段**，与「按时间」共用同一个分段方式；网格不分组，不显示分段方式。
- 分段下拉框去掉左侧的「分段」二字（可读名称仍为「按时间分段的方式」）；文案由「近一周按天，更早按月」改为「最近优先」，**筛选与分段逻辑不变**。

### 3. 阅读流显示附图缩略图

- 卡片顶部写「· N 张图」，正文下方最多露出三张 120×84 裁切缩略图，多于三张显示 `+N`；图片懒加载，读不到时留占位，不影响正文与其他内容。
- 新能力：`loadImageIndex(noteIds)` 一次取回一批手记的图片摘要（ID、显示名、原文件名、宽高），**不含相对路径与字节**；缩略图仍由既有 `memocraft-image` 协议按图片 ID 取图，渲染端依旧拿不到文件位置。
- 一次最多 200 条手记，超过由渲染端分批请求；服务端对超出上限或非法标识明确报错。

### 4. 归纳详情：连读与网格

- 归纳详情新增页头一行：左侧是说明（作导语只读显示）与「N 条手记 · 创建于 …」，右侧是**排列顺序**（最新在前 · 最早在前）与**呈现方式**（连读 · 网格）。
- **连读**为默认呈现：每条手记一个带序号的小节（标题、分类 / 时间 / 标签、完整 Markdown 正文、附图缩略图、「另见『X』」），右侧「本页目录」随滚动高亮当前小节，点击目录平滑滚动并让开固定标题栏；悬停或键盘聚焦小节时出现「打开」与「移出」（移出走提示条撤销）。窄窗隐藏右侧目录。
- **网格**保留原来的两列卡片与悬停「移出」。
- 顺序对两种呈现同时生效，默认仍是最新在前。

### 5. 偏好

新增两项本机偏好：归纳详情的呈现方式（默认连读）与排列顺序（默认最新在前）；随手记的三项不变，阅读流的分段开关取消。全部存在 `localStorage`，读取失败退回默认，写入失败照常切换并提示。

## 已知限制与遗留问题

- **阅读流一次渲染整列 Markdown**：手记数量很大时的滚动性能仍未测量，出现卡顿再改为按可见区渲染（沿用上一轮交付的结论）。
- **缩略图是只读装饰**：读不到图片时不显示缩略图并提示一次，不影响正文；列表不会显示尚未落库的图片。
- **发现一处遗留缺陷（未在本次修复）**：[App.vue](../src/renderer/src/App.vue) 的切页滚动记忆与 [ThreadsPage.vue](../src/renderer/src/pages/ThreadsPage.vue) 的「回到列表顶部」仍对 `window` 调用滚动，而窗口本身不滚动（滚动容器是 `.main`），因此这两处实际不生效。归纳页已改用 [scroll.ts](../src/renderer/src/scroll.ts) 的实际容器；其余两处按「不扩大本次任务范围」记录在此，可另行安排。
- 归纳详情默认「连读」是本次的产品决定；如需改回默认网格，只需把 `readTopicDetailLayout` 的默认值与文档同步。
