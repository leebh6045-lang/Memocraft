# V2 阶段 5 交付 · 备份、恢复与可读导出 · 2026-09-23

## 本轮成果

按 [V2 实施规划](V2实施规划.md) 第 4 节完成阶段 5：设置页的「数据」区、活动库替换式恢复、中断保护与 Markdown 可读导出。这是 V2 里唯一会替换活动数据的操作，因此失败路径的验证优先于新功能。

- **备份**：沿用 V1.5 的目录包格式（数据库快照 + `attachments/` + SHA-256 校验清单），由主进程弹出保存对话框选位置，返回真实摘要（时间、体积、附件数量）。
- **恢复分两步**：① 选择备份后先**校验并展开到暂存目录**，此时当前数据一点没动，并把包里的内容统计（手记／归纳／事务／动态／附件）显示给用户确认；② 确认后才替换活动库。
- **替换有保护**：替换前把当前数据整体复制成恢复前备份并写下进行中标记；替换后重新打开并校验；任一步失败或进程中断都会回滚到恢复前的数据。
- **启动检测**：启动时若发现未完成的恢复标记，先回滚再打开库，并通过界面提示告诉用户；标记存在但恢复前备份缺失时拒绝启动，绝不把半套数据当正常库打开。
- **可读导出**：把正文与关系元数据写成 Markdown（`index.md` + `手记/`、`归纳/`、`事务/`），文件名含稳定 ID，标题里的平台非法字符被清理，软删除内容不导出。
- **长任务表达**：备份、导出与恢复暂存按操作使用 10 分钟超时（普通请求仍为 30 秒），界面显示「进行中 · 不能取消」的不确定进度，不显示假百分比。

- `src/storage/recovery.ts`：恢复保护装置（恢复前备份、进行中标记、回滚、启动检测、应用暂存）。

- `src/main/library-data.ts`：主进程编排——对话框取路径、恢复的关库／替换／重开／提交或回滚。
- `src/main/ipc/register.ts`、`src/main/store-client.ts`：数据通道（渲染端不接触路径）与按操作区分的超时、存储线程重开。
- `src/renderer/src/pages/SettingsPage.vue`：设置页「数据」区与恢复确认对话框。

## 期间修正的实际缺陷

1. **`cpSync` 拒绝把目录复制进自己的子目录**：恢复前备份就在数据目录内，整目录复制会直接报错。改为逐项复制并跳过保护文件本身——这条只有真跑恢复才会暴露。
2. **恢复成功后界面仍显示旧数据**：活动库被替换，但渲染端还持有替换前的内存列表。设置页现在在恢复完成后通知外壳重读手记、归纳、事务与回收站。
3. **层间边界违规 4 处**：渲染端与 `shared/contracts.ts` 反向依赖 storage 取类型，被 ESLint 的导入限制拦下。数据形状下沉到 `src/domain/library-data.ts`，三层共用同一份定义。
4. **导出原本会清空目标目录**：改为目标已存在且不为空时拒绝，绝不删除用户已有文件（新增用例覆盖）。
5. **导出文件名不再用控制字符正则**：改为按码点剔除控制字符，既避免 lint 禁用规则，也不会在名字里插入多余空格。

## 与规划的差异

- **恢复拆成「校验」与「替换」两步**，中间给用户看备份内容统计；规划只要求"恢复前校验 + 确认"，这里让确认信息来自真实包内容而不是猜测。
- **进度是不确定态**（动画条 + 「进行中 · 不能取消」），不显示后端并未提供的百分比。
- **重活留在存储线程、替换在主进程**：备份、导出与恢复暂存都在存储线程执行；替换时必须先让持有数据库连接的线程退出，因此由主进程完成文件级替换后再重开线程。
- **回滚是自动的**：失败与中断都回到恢复前的数据，用户不需要手工操作；只有回滚本身失败才如实报错并保留标记。

## 数据兼容

**本轮没有数据库迁移**，模式版本仍是 4；备份包格式仍是 `formatVersion: 1`，V1.5 生成的备份可以直接恢复。恢复会把旧版本的备份在副本上迁移到当前模式后再替换活动库。

## 剩余限制

- 备份不含压缩、增量与保留策略；恢复过程不可取消（界面已明确说明）。
- 导出是可读快照：不含草稿、附件二进制与数据库结构，不能代替备份（`index.md` 里已写明）。
- 没有自动备份调度与备份提醒。
- 平台证据仍只有 macOS arm64；Windows 未验证（阶段 6）。
- 另注：`resources/brand/v2/` 是并行加入的品牌候选素材，本轮只把它排除在格式化检查之外，未改动其中任何文件。
