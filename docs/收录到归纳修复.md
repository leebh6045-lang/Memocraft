# 修复「收录到归纳」方向错误 · 2026-09-24

## 问题

手记详情抽屉里的「收录于归纳 → ＋ 收录到归纳」打开的却是**归纳侧的手记选择器**（标题「收录手记」，提示「选择要收录到当前归纳的手记」），列的是手记而不是归纳，用户无法选择"这条手记要收录到哪个归纳"。

代码链路：

1. `NoteDrawer.vue` 点按钮打开 `NotePickerDialog`（归纳侧用的手记选择器）；
2. `confirmCollect(topicIds)` 把选择器返回的**手记 ID** 当**归纳 ID** 逐个上报；
3. `TopicStore.addNotes` 第一步 `this.require(id)` 查不到该归纳，抛 `NOT_FOUND`；
4. `useTopics.addNotes` 只把原因写进 `topicState.error`，而它只在主题归纳页渲染，`collectIntoTopics` 失败时直接返回——**界面完全没有反馈**，用户看到的只是对话框关掉、什么都没发生。

`docs/阶段1设计-主题归纳.md` 第 194 行早已写明正确形态：「收录到归纳…」按钮打开同一个选择器，选择器需要支持「选已有归纳」。这个模式当时没有实现，手记抽屉却已经接到归纳侧的模式上。

不会写坏数据：`addNotes` 在事务内先校验归纳存在，抛出即回滚，外键也开着，不产生孤儿收录行。

## 修复

- **选择器改为双向共用**：新增 `src/renderer/src/components/PickerDialog.vue`（通用选择器）与 `src/renderer/src/picker.ts`（条目构建），替换原来的 `NotePickerDialog.vue`。两个方向的差别收敛到条目与文案：
  - 归纳侧列**手记**：已经在这个归纳里的不再列出，只回报数量用于空状态（行为不变）；
  - 手记侧列**归纳**：全部列出，已收录的带「已收录」标记且不可重复选择（不再靠"消失"表达状态）。
- **「已收录」语义按方向各自计算**，由 `topicPickerOptions(topics, linkedIds)` / `notePickerOptions(notes, linkedIds)` 在调用方算好，选择器本身不再接收含义模糊的 `collected-ids`——原来的错位（把"所属归纳 ID"当"已收录手记 ID"）在结构上不可能再出现。
- **手记侧可就地新建归纳**：选择器底部「＋ 新建归纳」打开抽出来的 `TopicCreateDialog.vue`（归纳模块与抽屉共用同一张表单，含同名「仍要创建」确认）。创建成功后新归纳自动勾上，和已勾选的归纳一起提交。
- **失败可见**：`App.collectIntoTopics` / `removeNoteFromTopic` 失败时把原因交给手记抽屉，显示在「收录于归纳」下方（`role="alert"`）；抽屉每次打开时清空。事务侧 `关联手记` 失败原本也是静默的，一并改成提示。
