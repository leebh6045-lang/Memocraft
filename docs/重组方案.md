# 回顾页面视觉丰富化方案

> 本文档面向实现模型。以下改进建议均基于项目现有设计系统（theme.css 中的 CSS 变量与令牌），不引入新依赖，与其他模块保持一致的视觉语言。改进项按优先级排列，可分批实现。

---

## 现状问题分析

截图显示页面目前存在以下问题：

- 页面顶部大量留白，时间导航与内容之间空间未被充分利用
- 两张白卡片占满全宽，内容密度低，缺乏信息层次
- 没有任何数据可视化，所有统计数字（30 条手记）都被埋在角落文字里
- 「推荐」列表视觉上与普通 `<ul>` 无异，没有主次区分
- 整页用色单一，没有用到 `--c-todo`、`--c-done`、`--accent-soft` 等已有语义颜色

---

## 建议一：顶部数据概览条（优先级：高）

### 效果描述

在时间导航下方、主卡片上方插入一行横排的数据指标，直接从 `AiPeriodSummary` 的已有数据（noteCount、staleTodoCount 等）读取。无需新的 API 调用。

```
┌─────────────────────────────────────────────────────────────┐
│  📝 30 条手记    ✓ 12 条已完成    ⚠ 8 条待办    📚 5 个归纳  │
└─────────────────────────────────────────────────────────────┘
```

### 实现细节

**数据来源**：`summary.noteCount`（总数）已有；已完成数、待办数、活跃归纳数目前仅通过 prompt 的 `stats` 传给 AI，但 `activeTopics.length` 可以从 `PeriodNotesResult.stats` 取到。需要把 `staleTodoCount` 和 `activeTopics.length` 从 `AiPeriodSummary` 里作为可选字段透传到渲染端（或者在 `useReview` 里单独存一份 `stats`）。

更简单的方案（不改 API）：只展示 `summary.noteCount`，其余数字在首次生成完成后从 `summary.suggestions` 的文字里读取不可靠——建议扩展 `AiPeriodSummary` 增加两个可选字段 `statTodos?: number` 和 `statTopics?: number`，由主进程从 `PeriodNotesResult.stats` 回填。

**样式**：用 `display: grid; grid-template-columns: repeat(4, 1fr)` 排列，每格居中，指标数字用 `font-size: 20px; font-weight: 600`，说明文字用 `font-size: 12px; color: var(--muted)`。待办数不为零时数字颜色改为 `var(--c-todo)`，已完成数颜色改为 `var(--c-done)`。

**骨架屏**：在 loading 状态下，这一行换成 4 个宽度一致的 `skeleton-line`，高度 32px，与最终布局对应。

## 建议二：分类分布迷你图（优先级：高）

### 效果描述

「这段时间的积累」卡片内，摘要文字下方加一行手记分类分布条，用比例色块直观展示本期四类手记的构成：

```
收获 ████████████████ 18   待办 ████ 5   完成 ████ 6   杂项 █ 1
```

### 实现细节

**数据来源**：`PeriodNotesResult.notes` 在主进程里已经有每条手记的 `category`，按 category 计数后作为可选字段 `categoryBreakdown?: { insight: number; todo: number; done: number; misc: number }` 写入 `AiPeriodSummary`，主进程回填，不经过模型。

**样式**：用一个 `display: flex` 容器，每个分类对应一个色块，宽度按比例用 `flex-basis: ${pct}%` 控制，最小宽度 2px 避免零值消失。色块颜色：

- `insight`（收获）：`var(--accent)` 配 `opacity: 0.7`
- `todo`（待办）：`var(--c-todo)`
- `done`（完成）：`var(--c-done)`
- `misc`（杂项）：`var(--muted)`

色块下方有对应文字标签（分类名 + 数量），整行用 `gap: 2px`，圆角 `var(--radius-s)`。总条高 8px，加上文字标签整体高度约 36px。

**无障碍**：整个图表加 `role="img"` 和 `aria-label="本期手记分类：收获 18 条，待办 5 条，完成 6 条，杂项 1 条"` 的描述，色块之间有 2px 间距而不只靠颜色区分。

## 建议三：建议条目视觉分级（优先级：高）

### 效果描述

「推荐」列表目前是等权的实心圆点。建议改为带视觉权重的条目行，每条建议前加一个语义图标（对应「整理待办」「补充归纳」「继续学习」等意图类型），最重要的一条（第一条）卡片底色用 `var(--accent-soft)`，其余保持默认。

```
┌─────────────────────────────────────────────────────────────┐
│ ★ [accent-soft 底色] 有 8 条待办超过 7 天，建议优先处理…    │
├─────────────────────────────────────────────────────────────┤
│ ◎  「Vue 学习」收录了 5 条手记，可以补充归纳说明…           │
│ →  语言学习路径：c→js→vue，建议先从 b 站速通…              │
└─────────────────────────────────────────────────────────────┘
```

### 实现细节

不需要修改 AI 输出结构。纯前端根据条目索引处理：第一条（`index === 0`）用 `background: var(--accent-soft)` + `border-radius: var(--radius-s)` + `padding: 12px 14px`，其余条目用普通行样式 `padding: 8px 0`。

图标使用项目现有的 `AppIcon` 组件：

- 第一条用 `sparkle`（高优先级）
- 其余条目用 `chevron`（右箭头，表示「行动」）

或者更简单：完全不用图标，仅用背景色区分第一条，其余用项目已有的 `list-style: disc` 加上 `marker { color: var(--accent) }` 着色，这与 ReviewPage.vue 现有的 `.suggestions-card li::marker { color: var(--accent) }` 一致，直接增强即可。

## 建议四：周/月对比区块（优先级：中）

### 效果描述

在两张主卡片下方加一个轻量的「上一期对比」行，仅显示手记数量变化：

```
对比上一周：+12 条手记  ↑  较上周增加 67%
```

增加显示绿色（`var(--c-done)`），减少或持平显示 `var(--muted)`。

### 实现细节

**数据来源**：需要在渲染端读取上一期缓存（若存在）。`useReview` 里调用 `prevPeriod()` 后取缓存，但这样会切走当前页面。

更合适的方式：在 `summarize()` 返回时，主进程额外读取一次 `loadPeriodSummary(periodType, prevStartDate)` 并把 `prevNoteCount?: number` 附在结果里。或者在 `useReview.ts` 里维护一个 `prevSummary: Ref<AiPeriodSummary | null>`，在成功拿到当前结果后发起一次不显示 loading 的后台静默读取（`regenerate: false`，已有缓存时直接返回，无网络请求）。

如果觉得增加 API 复杂度，此条可以先跳过，等其他改进落地后再评估。

## 建议五：本期手记快览列表（优先级：中）

### 效果描述

在「推荐」卡片下方加一个可折叠的「本期手记」列表，展示最多 8 条手记的标题与分类徽章，与手记页面的列表视觉保持一致：

```
▼ 本期手记（30 条，展示最近 8 条）
   ┌──────────────────────────────────────────────┐
   │ [收获] HTTP/HTTPS 的请求-响应结构梳理          │
   │ [待办] JavaScript 进阶学习路径规划             │
   │ ...                                           │
   └──────────────────────────────────────────────┘
```

手记标题可点击，点击后触发 `emit('open-note', noteId)` 并由 App.vue 打开对应手记抽屉（复用现有 `openNote(id)` 路径）。

### 实现细节

**数据来源**：`PeriodNotesResult.notes` 目前只传给主进程，不回传渲染端。需要在 `AiPeriodSummary` 里增加 `recentNotes?: { id: string; title: string; category: NoteCategory }[]`（最多 8 条），主进程从 `fetchPeriodNotes` 的结果取 `notes.slice(0, 8)`，只保留 id、title、category 三个字段，不含 body。

**交互**：默认折叠，点击展开/收起。折叠状态存 `localStorage`，key 为 `review-notes-expanded`，下次打开时保持上次状态。展开时 `max-height` 用 CSS transition 动画，与项目其他展开效果一致。

**样式**：分类徽章复用 `.pick-badge` 的样式（`border: 1px solid var(--border); border-radius: 999px; font-size: 11px`），加上与主题一致的分类颜色（`insight: var(--accent)`，`todo: var(--c-todo)`，`done: var(--c-done)`，`misc: var(--muted)`）。

**无障碍**：展开/收起按钮加 `aria-expanded`，列表项用 `role="list"`，每项有明确的 `aria-label`。

## 建议六：时间导航区增加「跳至今天」（优先级：低）

### 效果描述

当用户导航到非当前时间段后，时间导航区右侧出现「今天」按钮，点击后快速跳回包含今天的时间段。当前时间段不显示此按钮。

```
< 上一周       2026年第39周（9月21日–9月27日）      今天  >
```

### 实现细节

在 `useReview.ts` 里增加一个 `isCurrentPeriod` computed：`periodRange(periodType, localToday()).startDate === startDate.value`。

`ReviewPage.vue` 里在「下一周/月」按钮旁增加：

```vue
<button v-if="!isCurrentPeriod" type="button" class="btn-ghost" @click="props.state.goToToday()">
  今天
</button>
```

`goToToday()` 在 `useReview.ts` 里实现为 `changePeriod(periodType.value, localToday(now()))`，已有 `changePeriod` 方法可直接复用。

## 建议七：生成时间的相对时间展示（优先级：低）

### 效果描述

卡片底部「上次生成于今天 11:58」改为「上次生成于 3 小时前」，鼠标悬停时气泡提示完整时间（已有 `:title="formatFullTime(summary.generatedAt)"`）。

### 实现细节

项目已有 `formatTime()` 函数（[src/renderer/src/format-time.ts](src/renderer/src/format-time.ts)），查看该函数是否支持相对时间格式；若不支持，参照其他模块（手记列表的时间显示）使用的工具函数扩展一个 `formatRelativeTime(isoString): string` 即可，逻辑：

- 5 分钟内：「刚刚」
- 1 小时内：「N 分钟前」
- 24 小时内：「N 小时前」
- 7 天内：「N 天前」
- 超过 7 天：回退到 `formatTime()`（日期格式）

## 实现顺序建议

按改动量从小到大、视觉收益从大到小排列：

1. **建议三**（建议条目视觉分级）：纯 CSS + 模板改动，不涉及数据层，最快落地，视觉提升最明显
2. **建议一**（顶部数据概览条）：需要主进程透传 2 个统计字段，改动集中，独立可测
3. **建议二**（分类分布条）：需要主进程透传 `categoryBreakdown`，与建议一可以同批处理
4. **建议六**（跳至今天）：纯前端，改动量小
5. **建议七**（相对时间）：工具函数扩展，改动量小
6. **建议五**（手记快览）：涉及结构变化最多，建议最后实现并同步评估是否需要
7. **建议四**（上期对比）：需要额外的读取逻辑，可选

---

## 注意事项

- 所有新增字段都是 `AiPeriodSummary` 上的**可选字段**（`?:`），旧缓存读取不会失败，仅不显示对应区块
- 骨架屏需要随新区块同步扩展，保持 loading 状态与最终布局高度匹配
- `prefers-reduced-motion` 样式已有全局处理，新增动画只需正常写 `transition`
- 分类颜色使用语义颜色令牌（`--c-todo`、`--c-done`、`--accent`），深色模式自动适配无需额外处理
