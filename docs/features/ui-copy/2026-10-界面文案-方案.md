# Memocraft 界面文案改进方案

建议让 Memocraft 的引导更像一句自然的邀请：帮助用户开始记录，允许内容暂时不完整，并在需要时说明下一步。温暖主要放在提示、空状态和说明句里；导航、分类、按钮和数据状态保持清楚、简短。

本方案依据 2026 年 10 月 13 日的实际源码，覆盖首页、手记、归纳、事务、设置、AI、回顾、搜索、标签、图片及删除恢复中的主要文案。以下是可供选择的建议稿，尚未替换界面文字，也不作为已采纳的产品规范。表中的位置标识对应文末源码索引，行号为本次审计时的位置。

## 1. 推荐的表达尺度

| 场景     | 推荐表达                                   | 判断依据                                                   |
| -------- | ------------------------------------------ | ---------------------------------------------------------- |
| 开始记录 | “先记下此刻的想法，标题和标签可以慢慢补。” | 降低开始的压力，明确哪些可以不填。                         |
| 空白页面 | 说明这里能放什么，再给一个当前可用的入口。 | 用户比起知道“没有内容”，更需要知道如何开始。               |
| 可选字段 | “可以”“需要时”“稍后补”。                   | 不让标题、标签、图片变成额外任务。                         |
| 操作完成 | “已保存”“已收录”“已移到回收站”。           | 结果比情绪表达更重要。                                     |
| 操作失败 | 发生了什么、哪些内容仍在、现在能做什么。   | 只有当前路径确实保留内容，才能写“输入仍保留”。             |
| AI       | 推荐、参考、查找、回顾。                   | 不把建议写成自动整理的结果，不把检索失败写成全库没有记录。 |

适量使用“你”，不用每句话都称呼用户。不增加打卡、催促或成就评价，也不使用“乖”“宝贝”“我永远替你保管”等过度亲密或无法兑现的表达。品牌统一写作 `Memocraft`，技术名称统一写作 `AI`、`API 密钥`、`Markdown`。

## 2. 优先修正：容易造成误解的文案

这些建议的理由是准确性，应先于单纯的语气润色。

| 编号 / 位置              | 当前文案                                                   | 推荐文案或处理                                                                                                                                                     | 理由与条件                                                                                                                                                              |
| ------------------------ | ---------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------ | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| A1 · ASK:66              | 你的手记里还没有关于这个的记录                             | 这次还没找到相关手记，试试换个关键词。                                                                                                                             | 实际是本地检索无命中，不能由此断言用户没有记录。AI 生成回答中的同类兜底句也须同步改为“这次找到的手记摘录里，暂时没有足够的信息回答这个问题”，见 ASK-S:231。             |

| A4 · ND:321、PICK:40–42  | 还没有归纳，先新建一个再收录。                             | 没有搜索词且确实无归纳：还没有归纳，可以先新建一个。；搜索无命中：没有找到匹配的归纳，试试换个词，或新建一个。                                                     | 搜索无命中时也可能显示现有空文案，不能误称全库没有归纳。实施时需按上下文选择，不能只做字符串替换。                                                                      |
| A5 · RV:310              | 覆盖 N 条手记                                              | 生成时本期共 N 条手记                                                                                                                                              | N 是生成时的本期总数，AI 使用的是摘录，超过 20 条还会采样。“覆盖”容易被理解成逐条读过完整内容。可补一句“回顾依据手记摘录生成，较多时按分类选取”，不要虚构实际发送条数。 |
| A6 · SET:121             | 已备份 N 个附件                                            | 备份已完成，包含 N 个图片附件。                                                                                                                                    | 备份还包含数据库与校验清单，不能让用户以为只备份了附件。零附件时也应明确备份完成。                                                                                      |
| A7 · LIB:37、97          | 保存未完成，输入仍在。请重试。                             | 作为保存失败的兜底句保留；加载失败单独用“知识库暂时无法读取，请重试。”                                                                                             | 当前加载与保存共用错误兜底。未完成加载时，不能无依据地声称“输入仍在”。已知业务错误仍应保留具体原因。                                                                    |

其中 A3、A4、A7 需要少量按场景区分的展示逻辑；A1 涉及模型回答兜底句的一致性。它们应单独落实和验证，不混同于一次批量替换。

## 5. 建议的第一轮范围

第一轮先处理 A1–A7，并纳入 B17、B24 这两项准确性补充；B2 属于展示规则的澄清，可一并处理。语气改进优先选 B1、B4、B7、B9、B10、B12、B14、B19、B21、B28、B29。其余候选放第二轮，结合真实使用决定是否值得增加文字。

若希望第一轮仅改固定字符串，可先落地不涉及状态判断的部分；A3、A4、A7、B21 单独处理。所有条目目前都只是方案，实施前需同步核对对应调用方及当前规范。

验收关注四点：

1. 初次进入页面时，能明白可以做什么；可选字段不会让人觉得必须补全。
2. 主按钮和短标签仍易于扫描，首页编辑区不增加长篇说明或重复提示。
3. AI、保存、删除、恢复和备份文案与实际行为一致；条件文案覆盖对应状态。
4. 按当前窗口配置的最小尺寸 1000 × 700 验证浅深主题、设置分类和抽屉；允许说明自然换行，标题和按钮不得截断、遮挡或挤压控件。标题、屏幕阅读器标签、成功和失败提示用词一致。正式替换后再做界面与相关流程验证。

实施后的必要场景：

| 场景                                         | 预期                                                                                         |
| -------------------------------------------- | -------------------------------------------------------------------------------------------- |
| A1：本地无命中；有命中但摘录无法回答         | 分别说明“这次没找到”和“这次摘录信息不足”，不推断全库从未记录。                               |
| A2：官方地址、自定义地址；有图片、图片被跳过 | 正确说明已保存的接收地址；图片参与与跳过按本次实际回执描述。                                 |
| A3：归纳收录、事务关联、动态引用三个入口     | 标题、确认按钮和全部已选的空状态使用各自关系名称。                                           |
| A4：真正没有归纳；已有归纳但搜索无命中       | 前者引导新建，后者引导换关键词或新建。                                                       |
| A5：超过 20 条手记；查看旧缓存               | 总数仍表示生成时本期总数，不表示完整阅读数，也不称旧缓存为最新结果。                         |
| A6：零图片与多图片备份                       | 都明确完整备份已完成，不让零附件看起来像没有备份。                                           |
| A7：加载失败；保存失败                       | 加载提示不声称输入仍在；保存提示只按实际保留状态反馈。                                       |
| B21：状态未知、无密钥、有密钥                | 分别使用“AI 服务”“为 Memocraft 接入 AI”“管理 Memocraft 的 AI 服务”；保存密钥不显示连接成功。 |

本轮仅做源码文案及行为核对，没有运行桌面程序，也未进行新文案的视觉验证。此方案没有改动界面代码，不以功能测试证明尚未实施的体验变化。
