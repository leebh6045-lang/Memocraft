# 帮助网站设计

## 页面与源码

正式源码位于 `website/help/index.html`。HTML、CSS、JavaScript 与图形均在这一文件中，直接由 Nginx 提供，无需构建或额外运行时。临时原型留在本地原型目录，正式源码不依赖该目录。

页面按用户已确认的版式保留六段教程：奇数段演示在左、讲解在右，偶数段反向；窄屏统一先文字后演示。应用配色用于示例控件，正文保持充足留白。章节入场只执行一次，遵守系统减少动态偏好。

## 示例与内容边界

示例状态只保留在当前文档内，不访问 Electron 桥接、网络 API 或浏览器持久化存储。用户输入通过 `textContent` 写入结果；固定示例模板不拼接输入。

教程依照当前应用行为说明：默认收获，待办通过改分类完成；手记可以多重收录；草稿和回收站不参与搜索；完整备份用于恢复，Markdown 导出不包含草稿和图片文件。AI 在常见问题中简述，不作为开始记录的前提。

## 部署流程

1. 使用用户指定的 SSH 凭据连接，复用已有服务器指纹，先检查系统、Nginx 启动参数、配置入口、包含文件及站点目录。
2. 根据实际站点选择独立路径和静态目录。现阶段没有域名，先取得可验证的 IP 访问网址；路径和服务器目录在检查后记录，不猜测既有配置。
3. 将正式 HTML 上传到暂存位置，核对摘要；如目标已有页面，先备份，再替换正式文件。
4. 确需新增 location 或站点配置时，只修改已确认的配置位置，并保留修改前备份。
5. 执行实际 Nginx 的配置检查，成功后重载；验证服务器本机请求、外部访问、页面类型、内容摘要和受影响的已有入口。
6. 将实际部署结果补充为交付文档；服务器地址、登录用户名、私钥路径和具体机器记录保留在本地部署记录中。

## 失败与后续接入

认证失败时不上传文件或修改服务器；本地加密私钥由用户在终端解锁。权限不足时确认所需管理操作，不改 SSH 登录策略。Nginx 配置检查失败时不重载，修复或还原本次配置；重载后访问异常则依据备份还原并验证。

实际部署使用 `/memocraft/help/` 独立路径，静态文件独立于既有网站的发布目录。未带结尾斜线的入口重定向到标准路径。实际站点配置先备份，只插入帮助路由，配置检查通过后重载。

当前阶段不改应用 IPC、数据库或应用窗口策略。后续问号入口通过有限 preload API 交由主进程打开系统浏览器，并保持现有编辑现场。

## 验证计划

页面在浏览器检查六段交互、空白输入、无匹配搜索、桌面交替布局以及 390px 和 320px 窄屏；核对 HTML 锚点、重复 ID、脚本语法与格式。正式文件若与已验证原型完全一致，可复用对应页面验证，并核对复制摘要；部署后另做实际访问验证。
