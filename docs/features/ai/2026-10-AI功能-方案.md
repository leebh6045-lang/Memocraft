# Memocraft AI 功能实现规划

> 本文保留三个 AI 功能的产品规划。当前厂商已确定为 DeepSeek，模型支持 V4.1 Flash 与 V4 Pro；各阶段开工前须补独立任务书与设计文档。第一阶段已交付，用户确认连接成功；第二阶段已完成归纳建议与图片输入，用户确认手动测试均正常，见 [交付记录](2026-10-AI归纳建议-交付.md)。第三阶段已按 [搜索问答任务书](2026-10-AI搜索问答-任务书.md) 与 [设计文档](2026-10-AI搜索问答-设计.md) 实现，实际验证见 [搜索问答交付](2026-10-AI搜索问答-交付.md)，检索与来源边界见 [决策 007](../../decisions/007-搜索问答的检索与来源边界.md)。阶段三真实供应商手动验收待完成。周期总结已按 [阶段四任务书](2026-10-AI周期总结-任务书.md) 与 [设计](2026-10-AI周期总结-设计.md) 实现；实际验证见 [交付](2026-10-AI周期总结-交付.md)。下方保留的接口示意不是当前契约，具体以阶段设计为准。

## 总体架构约束

所有 AI 功能必须遵守项目现有的进程边界规则（开发准则第 4 节）：

```
renderer（Vue 组件）
  → preload（IPC 接口暴露）
  → main 进程 AI 服务（通过存储线程检索、管理密钥、调用客户端）
  → 已保存的 DeepSeek 兼容 API 地址（默认官方）
```

**禁止**在 renderer 进程直接调用任何外部 API。API Key 通过设置页写入主进程，使用 Electron 的 `safeStorage` 加密后保存在知识库目录之外，不得明文落盘、回读到页面或进入知识库备份/导出。系统加密不可用时不允许明文降级。模型配置保存在 SQLite。

### 共享类型

**[src/shared/ai.ts](../../../src/shared/ai.ts)** 已定义模型、配置与测试契约，阶段二追加建议契约；下方问答与周期总结保留早期示意，当前类型以阶段三/四设计与实际代码为准：

```typescript
// AI 功能共用类型

export interface AiSuggestion {
  tags: string[]; // 建议标签列表
  topics: { id: string; title: string }[]; // 本次候选内的现有归纳，标题由本地回填
}

export interface AiAnswer {
  answer: string; // 模型回答正文（≤3句）
  sourceNoteIds: string[]; // 引用的手记 ID 列表
}

export interface AiPeriodSummary {
  period: 'week' | 'month';
  startDate: string; // ISO 8601
  endDate: string; // ISO 8601
  summary: string; // 主题与积累概要
  suggestions: string[]; // 建议操作列表（≤5条）
  noteCount: number; // 覆盖手记数
  generatedAt: string; // 生成时间，区分当前统计与旧缓存
}
```

### 主进程服务

**[src/main/ai-service.ts](../../../src/main/ai-service.ts)** 协调配置、凭据与连接测试；[DeepSeek 客户端](../../../src/services/deepseek-client.ts) 负责请求和响应校验。三个功能随后按职责增加业务服务，共用调用基础。默认 `deepseek-flash`，用户可选择 `deepseek-v4-pro`；不把三个功能全部堆入同一个文件。

### 需扩展的 preload

第一阶段在 preload 中新增 `ai` 命名空间，暴露加载设置、保存模型、保存/清除密钥、测试/取消连接；均返回 `Result<T>`。阶段二追加 `suggest` / `cancelSuggestion`，建议输入与取消契约见阶段二设计；下方问答与周期总结保留早期接口方向，当前入口为 ask / summarizePeriod，详见对应设计：

```typescript
ai: {
  suggest: (input: AiSuggestionInput) => Promise<Result<AiSuggestion>>;
  cancelSuggestion: (requestId: string) => Promise<Result<null>>;
  askQuestion: (question: string) => Promise<Result<AiAnswer>>;
  getPeriodSummary: (input: {
    period: 'week' | 'month';
    anchorDate: string;
    regenerate: boolean;
  }) => Promise<Result<AiPeriodSummary>>;
}
```

### 设置页 API Key 管理

在 [SettingsPage.vue](../../../src/renderer/src/pages/SettingsPage.vue) 新增「AI 设置」区块，交互由独立 [AiSettingsPanel.vue](../../../src/renderer/src/components/AiSettingsPanel.vue) 承担：

- 厂商固定显示 DeepSeek，提供 Flash / Pro 模型选择，选择后自动保存
- API 地址默认官方，可自行填写 Base URL、保存或恢复官方，详见 [自定义地址设计](2026-10-AI自定义地址-设计.md)
- 文本输入框填写 DeepSeek API Key（输入框类型为 `password`，不明文展示）
- 保存后通过 IPC 传至主进程，用 `safeStorage.encryptString` 加密后写入独立凭据目录
- 显示当前状态：未配置 / 已配置（不显示 Key 内容）
- 提供「清除」操作
- 测试连接实际生成短回答；配置状态与验证结果分开。失败、取消、超时不显示成功，细则见阶段一设计

## 功能一：归纳建议

> 本功能的实现依据已细化为 [任务书](2026-10-AI归纳建议-任务书.md) 与 [设计文档](2026-10-AI归纳建议-设计.md)，输出边界见 [决策 006](../../decisions/006-归纳建议的候选与输出边界.md)。下方保留产品层面的定位与交互意图，契约与校验以阶段设计为准。

### 定位

用户在首页草稿编辑区写完手记内容后，点击「AI 建议」按钮，获取标签建议和归入现有归纳的建议。触发时机是**保存前的主动操作**，不自动触发，不干扰默认写作流程。

### 触发入口

位置：首页 [src/renderer/src/pages/HomePage.vue](../../../src/renderer/src/pages/HomePage.vue) 的工具栏区域，在现有「保存手记」按钮左侧新增「✦ AI 建议」按钮。

- 正文为空时按钮禁用（`disabled` 状态）
- 点击后按钮进入加载状态（显示旋转图标，禁用重复点击）
- 未配置 API Key 时点击弹出提示引导至设置页

### 结果展示

建议以内联展开卡片的形式出现在编辑区下方、草稿状态之前，不弹出遮罩层：

```
┌─ ✦ AI 建议 ────────────────────────────────────┐
│  标签建议：  [Vue.js] [响应式] [Composition API]  │
│  可归入归纳：[Vue 学习 →] [前端工程化 →]           │
│                                   [关闭]        │
└────────────────────────────────────────────────┘
```

- 标签建议：每个标签显示为可点击胶囊，点击后直接添加到当前手记的标签中（通过 `library.changeDraft()` 更新，沿用草稿自动保存）；已存在的标签显示为已选中状态不可重复添加
- 归纳建议：只显示库中**已存在**的归纳，不凭空创建；点击「→」跳转到对应归纳（不在此处执行收录操作，收录由用户在归纳页自主完成）
- 建议卡片有「关闭」按钮，关闭后重新点击「AI 建议」可再次生成

### 实现与边界

独立 `AiSuggestionService` 复用 `AiService.resolveCallContext()` 取得模型与密钥，负责候选预筛、prompt、输出校验及取消；入口使用 `ai.suggest` / `ai.cancelSuggestion`。

- 输入正文非空且最多 4,000 字符、标题最多 300 字符；实际发送正文前 800 字符。
- 归纳候选本地预筛到最多 30 个，模型只返回 `topicIds`，未知 ID 丢弃，标题由本地回填。
- 标签参考包含草稿已有标签与知识库高频标签，合计最多 40 条；不发送完整标签池。
- prompt 目标为 3–5 个标签、每项不超过 10 字符；合法输出为 0–8 个、每项不超过 30 字符，以及 0–3 个归纳。两字段严格校验字符串数组，原始数量先检查再去重和白名单过滤；非法输出整份报错，合法空结果显示「没有找到合适的建议」。
- 模型返回的草稿已有标签保留并显示为已选中；满 100 个标签时拒绝新增。归纳点击先保存草稿、确认导航成功，再打开详情。
- 建议不落库、不自动采纳；正文修改后有内容和空结果均标为可能过期。切页、关闭卡片取消匹配请求，窗口关闭与知识库恢复等待所有 AI 请求和配置写入结算，恢复期间暂停新的 AI 入口。Flash 可同时分析经草稿归属校验的最多 4 张图片（累计 base64 ≤8 MiB），Pro 只分析文字并提示切换 Flash；图片超预算、超尺寸或不可读时跳过并报告数量，增删图片同样令旧建议过期。

## 功能二：RAG 问答（搜索增强）

> 本功能已细化为 [任务书](2026-10-AI搜索问答-任务书.md) 与 [设计文档](2026-10-AI搜索问答-设计.md)，检索与来源边界见 [决策 007](../../decisions/007-搜索问答的检索与来源边界.md)。下方保留产品层面的定位与交互意图；**履约细节以阶段设计为准**，与本节不一致时以阶段设计为准（例如展开视图改为在搜索面板内展开，不叠第二层浮层；本阶段不发送图片）。

### 定位

扩展现有搜索面板 [SearchPalette.vue](../../../src/renderer/src/components/SearchPalette.vue)，在关键词搜索结果上方插入一行 AI 摘要。用户感知是「搜索变聪明了」，而不是「打开了一个对话功能」。

### 交互设计

搜索面板内，当搜索词长度 ≥ 4 个字符时（避免单字母触发），在搜索结果列表上方显示 AI 摘要行：

**状态一：加载中**

```
  ✦  正在从你的手记中查找…
```

**状态二：有结果**

```
  ✦  你在3条手记里记录过 ref 和 reactive 的区别，核心是…  [展开 →]
     来源：#42 #17 #31
```

- 摘要截断为一行（约 40 字），超出显示省略号
- 「展开 →」点击后，在搜索面板**右侧**滑出详情浮层（复用 [SideDrawerPanel.vue](../../../src/renderer/src/components/SideDrawerPanel.vue) 的容器样式），展示完整回答和来源手记卡片（可点击跳转）
- 来源标注 `#id` 可点击，直接导航到该手记详情

**状态三：无相关手记**

```
  ✦  你的手记里还没有关于这个的记录
```

**状态四：未配置 API Key**
不显示 AI 摘要行，搜索功能正常使用，不降级体验

### 防抖与缓存

- 搜索词变化后 600ms 无进一步输入才触发 AI 请求（防止每次击键都请求）
- 同一搜索词的结果在本次搜索面板打开期间缓存，关闭后清空

### 主进程实现（ai-service.ts 中的 askQuestion）

**检索层**：当前 [search-store.ts](../../../src/storage/search-store.ts) 是整个关键词的 LIKE 子串匹配，按更新时间排序，没有 FTS 或相关度排名。问答阶段须设计独立上下文检索入口，明确查询词处理、候选排序和摘录方式；不能直接把完整自然语言问题交给现有搜索并声称具备语义召回。首轮不预建向量数据库。

**Prompt 结构**：

```
系统：你是用户的个人知识助手。根据下面的手记摘录，用不超过3句话回答用户的问题。
      如果手记中没有相关信息，直接说"你的手记里还没有记录这方面的内容"。
      回答时在句末用括号标注引用来源，如（来自手记#42）。
      不要编造手记中没有的内容。

手记摘录：
[手记 #42] <title> | <正文前300字>
[手记 #17] <title> | <正文前300字>
...

用户问题：<搜索词>
```

**输出解析**：上面的数字编号只作为本次回答的展示编号，实际手记 ID 是 UUID。模型返回结构化来源编号，主进程按本次候选映射到真实 UUID 并校验；不以 `#\d+` 作为数据库 ID，不接受凭空编造的来源。

## 功能三：周期路线总结

> 已按阶段四任务书与设计实现。以下保留产品规划，实际缓存分列存储，不存 end_date；图片预算、采样与取消以阶段四设计为准。

### 定位

放置在左侧边栏四个主功能模块**下方**，用一根两端渐细（opacity 渐变）的横线与主功能区隔开，作为扩展功能入口。入口标题为「回顾」，图标选用日历或时间线类图标。

### 侧边栏布局变更

修改 [src/renderer/src/App.vue](../../../src/renderer/src/App.vue) 或侧边栏组件，在导航列表底部插入：

```
  ─ ─ ─ ─ ─ ─ ─ ─ ─（两端渐细分隔线）─ ─ ─ ─ ─ ─
  📅  回顾
```

分隔线实现：`background: linear-gradient(to right, transparent, var(--border), transparent)`，高度 1px，上下各留 12px 间距。

### 功能页面（新建 ReviewPage.vue）

路径：`src/renderer/src/pages/ReviewPage.vue`（阶段四已实现）。

页面结构：

**顶部切换**：「按周」/ 「按月」两个选项卡，默认「按周」

**时间导航**：

```
  ← 上一周    2026年第41周（10月5日 - 10月11日）    →
              本周记录了 12 条手记
```

**内容区**：分两部分

1. **总结卡片**：
   - 标题「总结」
   - 展示模型生成的主题概要（段落文本）
   - 右下角显示生成时间戳

2. **建议列表**：
   - 标题「推荐」
   - 最多 5 条建议，每条一行，前缀用 `·`
   - 建议内容指向具体操作（如「有3条待办手记超过7天未处理」「"Vue 学习"归纳下有5条手记，可以补充归纳说明」）

**状态处理**：

- 当前时间段内手记数为 0：显示「这段时间没有新手记」，不请求 AI
- 首次查看某个时间段：自动触发生成（加载中状态显示骨架屏，结构与最终布局一致）
- 已生成过的时间段：直接展示缓存结果，右下角显示「上次生成于 xx」，提供「重新生成」按钮
- 未配置 API Key：显示引导提示，指向设置页

### 缓存策略

生成结果缓存到 SQLite（新建 `ai_period_summaries` 表，字段：`period_type`, `start_date`, `end_date`, `content_json`, `generated_at`）。同一时间段的手记数量或内容变化后，旧缓存仍保留，用户可手动点「重新生成」刷新。不自动失效。

### 主进程实现（ai-service.ts 中的 getPeriodSummary）

**数据获取**：按 `created_at` 范围从数据库取该时间段全部手记，获取 `id`、`title`、`category`、正文前 200 字（避免 prompt 超长）。

周期阶段须明确本地自然周/自然月及 UTC 半开查询范围，支持锚点日期与手动重新生成，返回生成时间。精确的待办年龄与归纳收录数量先由数据库计算，模型只依据这些事实组织建议；不能从正文采样推测全量统计。回顾采用当前有效手记及当前分类，不声称有历史状态快照。

**手记数量过多时的处理**：若手记超过 20 条，按 `category` 分组后各取代表性条目（每组最多 5 条），在 prompt 中说明总数，避免截断重要内容。

**Prompt 结构**：

```
系统：你是用户的个人知识助手，帮助用户回顾一段时间的学习积累。
      根据下面的手记列表，完成两件事：
      1. 用2-4句话概括这段时间的主要学习主题和知识积累方向
      2. 给出最多5条具体可操作的建议（如"XXX归纳下有较多手记，可以补充归纳说明"，
         "有N条待办超过7天，可以处理或改为完成"等）
      建议要具体，不要泛泛而谈。
      返回 JSON，格式：{"summary": "...", "suggestions": ["...", "..."]}

手记列表（共 N 条，时间范围：<start> 至 <end>）：
[#1] 收获 | <title> | <正文前200字>
[#2] 待办 | <title> | <正文前200字>
...
```

**输出解析**：解析 JSON，封装 `AiPeriodSummary` 返回，同时写入缓存表。

## 验收标准

- 未配置 API Key 时，三个功能均有合理的降级提示，不影响其他功能正常使用
- API 调用失败（网络错误、超时、余额不足）时，前端显示明确错误提示，不白屏、不静默失败
