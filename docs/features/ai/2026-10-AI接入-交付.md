# AI 阶段一交付记录：设置与调用基础

> 已交付。2026-10-10 用户确认已手动测试，连接成功，并同意进入阶段二。未提供逐模型测试详情，不据此补写两个模型分别通过的记录。范围见 [任务书](2026-10-AI接入-任务书.md)，方案见 [设计](2026-10-AI接入-设计.md)。

## 1. 已实现行为

- 设置页增加独立 AI 区块，厂商固定 DeepSeek，模型可选 V4.1 Flash / V4 Pro，选择后自动保存。
- 密钥通过密码框保存、更换、清除。保存中按钮显示进度，成功后清空输入、在输入框旁显示绿色勾选确认卡片，并弹出「密钥已保存，可以测试连接」提示；已配置状态带醒目的勾选标识。确认卡片解释输入清空的原因，测试与配置重读不擦掉保存回执，重新输入或清除时撤下；失败保留输入，不显示成功。已保存密钥不回传页面。
- 系统加密后原子替换凭据文件；加密不可用、解密失败均有明确提示，不使用明文降级。
- 测试连接使用所选模型生成短回答，只有完整非空应答才显示成功与耗时；请求不发送用户笔记。
- 认证、余额、限流、网络、超时、格式异常分别反馈，支持取消，无自动重试计费请求。
- 主进程限制重复测试，页面离开取消自身请求，旧应答不能覆盖新状态。
- 关闭或恢复知识库时取消测试、等待已提交配置/凭据写入；在途写入失败保留窗口与输入。
- 密钥在知识库外独立保存；恢复知识库保留密钥，模型随数据库恢复，AI 区块刷新模型和测试状态。

## 7. 外部评估复核

2026-10-10 重新读取 [官方首次调用](https://api-docs.deepseek.com/)、[模型与价格](https://api-docs.deepseek.com/zh-cn/quick_start/pricing) 及 [思考模式](https://api-docs.deepseek.com/zh-cn/guides/thinking_mode)，核验外部评估中的两项判断：

- 官方当前列出的模型标识为 `deepseek-flash` 与 `deepseek-v4-pro`，对应 DeepSeek-V4.1-Flash 与 DeepSeek-V4-Pro-0813。截图以 V3 / R1 命名推断当前 V4 标识无效，这项结论不成立；保留现有模型名单与已经用于版本 6 数据库的迁移。
- 两个模型均支持思考开关，官方 OpenAI 格式为 `thinking.type = enabled / disabled`，不是 R1 专属。当前短文本调用显式关闭思考是既定选择，未增加无实际用途的模型分支。

错误提示中存在一处可改进之处：原来将所有未分类的 HTTP 失败提示为「检查所选模型」，会将程序构造请求的错误归因于用户选择。现已区分 400（请求格式）、422（请求参数）、404（模型/服务接口不存在），其他未分类错误也保留 HTTP 状态码，并引导更新应用或反馈问题；不暴露供应商原始正文、密钥，也不自动重试计费请求。分类依据 [官方错误码](https://api-docs.deepseek.com/zh-cn/quick_start/error_codes)。
