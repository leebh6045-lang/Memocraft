# AI 阶段三任务书：搜索问答

> 状态：已实现并完成类型、lint、572 项单元／SQLite集成和最终包 17 项桌面验证；真实供应商手动验收待完成，因此保持 `in-progress`。配套设计见 [AI 阶段三设计](2026-10-AI搜索问答-设计.md)，实际结果见 [交付记录](2026-10-AI搜索问答-交付.md)，边界决策见 [007](../../decisions/007-搜索问答的检索与来源边界.md)。本阶段以当前文档为验收依据。
> 前置阶段：[AI 阶段一：设置与调用基础](2026-10-AI接入-任务书.md)、[AI 阶段二：归纳建议](2026-10-AI归纳建议-任务书.md)。

## 1. 目标与范围

用户在全局搜索面板输入问题时，结果列表上方出现一行 AI 摘要，回答来自用户自己的手记并标注来源；点击来源可跳转到对应手记。用户感知是「搜索变聪明了」，而不是「打开了一个对话功能」。

**不新开功能页面**：问答是搜索能力的增强，入口就在既有的 `Cmd+K` 搜索面板内。

### 包含

- 搜索词长度达到 4 个字符时，在结果列表上方出现 AI 摘要行。
- 加载中、有结果、无相关手记、未配置密钥四种状态均有明确呈现。
- 有结果时摘要截断为一行（约 40 字），附「展开」入口。
- 展开后在同一面板内显示完整回答与来源手记列表；来源可点击跳转。
- 检索限定为**手记**（不含归纳、事务、动态），只取当前有效手记，不含草稿与回收站。
- 搜索词变化后 600ms 防抖；同一搜索词在本次面板打开期间命中缓存。
- 手记库中没有相关记录时，明确告知且**不调用模型**（不产生费用）。
- 未配置密钥时不显示 AI 摘要行，其余搜索功能完全不受影响。
- 密钥无效、余额不足、限流、超时、网络异常、返回格式异常均有明确反馈。

### 不包含

- 不做多轮追问与对话历史；每次提问独立，不携带上一问。
- 不新开页面、不新增侧边栏入口、不占用主功能模块位置。
- 不做流式输出（理由见设计文档第 9 节与决策 007）。
- 不预建向量数据库或嵌入索引；首轮是关键词多词检索加本地排序。
- **本阶段问答只依据文字**，不发送图片（理由见设计文档第 8 节；周期总结阶段再引入图片参与）。
- 不做跨手记的归纳总结、不做「你没有记录但可能想知道」的外部知识回答。
- 不修改任何手记内容；问答是只读操作。

## 2. 实施任务

1. 共享契约新增问答类型与请求、取消通道；preload 暴露 `ai.ask` 与 `ai.cancelAsk`。
2. 存储线程新增面向问答的检索操作：多词命中、字段加权排序、返回命中窗口摘录。
3. 主进程新增独立的问答服务：本地检索、prompt 组装、**来源编号映射到真实手记 ID**、输出校验。
4. 搜索面板新增 AI 摘要行与展开视图；接入防抖、缓存与取消。
5. 处理在途请求与关闭面板、切页、编辑手记、关闭窗口、知识库恢复的关系。
6. 补充单元、集成与桌面验收，完成后写交付文档。

## 3. 验收标准

| 编号 | 场景                                     | 预期                                                                             |
| ---- | ---------------------------------------- | -------------------------------------------------------------------------------- |
| C1   | 搜索词少于 4 个字符                      | 不显示 AI 摘要行，其余搜索行为不变                                               |
| C2   | 搜索词达到 4 个字符且库中有相关手记      | 出现加载状态，随后显示一行摘要与来源数量；结果列表照常显示                       |
| C3   | 展开摘要                                 | 面板内显示完整回答与来源手记列表；每个来源显示手记标题                           |
| C4   | 点击来源手记                             | 打开该手记详情（与点击搜索结果的行为一致）                                       |
| C5   | 库中无相关内容                           | 显示「你的手记里还没有关于这个的记录」；**不调用模型**                           |
| C6   | 未配置密钥                               | 不显示 AI 摘要行；搜索、跳转等全部照常工作；不出现错误提示                       |
| C7   | 密钥无效、余额不足、限流、网络失败、超时 | 摘要行位置显示对应错误与重试入口；失败不影响搜索结果的显示与跳转                 |
| C8   | 模型返回非法内容                         | 格式异常提示；**不展示来源编号未映射到真实手记的回答**；不出现凭空编造的手记标题 |
| C9   | 模型返回越界或重复的来源编号             | 越界编号丢弃并重新映射；全部越界时按无来源处理并在界面如实呈现                   |
| C10  | 快速连续输入                             | 600ms 防抖；同一搜索词不重复请求；在途时新搜索词先取消旧请求                     |
| C11  | 关闭面板、切页、开始编辑手记             | 在途请求被取消；迟到响应不覆盖新状态；不显示已离开现场的错误                     |
| C12  | 关闭窗口或恢复知识库                     | 在途问答请求被取消并等待结算；恢复失败保留窗口                                   |
| C13  | 重复查看同一搜索词（面板未关闭）         | 命中缓存，不产生第二次计费请求                                                   |
| C14  | 手记被编辑或删除后再次搜索同一词         | 缓存失效，重新检索与回答                                                         |
| C15  | 从版本 6 数据库升级                      | 无需迁移；原有内容、关系与 AI 配置不受影响                                       |

## 4. 验证与交付记录

自动化验证使用替身客户端与隔离数据目录，不访问真实知识库、不消耗真实额度。真实 DeepSeek 验证必须使用用户自己的密钥，在设置页输入，禁止写进文档、源码、命令参数或报告；没有有效密钥时相关条目保持未验证，不以模拟成功代替。

实际验证结果、已知限制与后续建议见 [交付记录](2026-10-AI搜索问答-交付.md)。

## 5. 依赖与风险

- 依赖阶段一：模型配置、加密凭据、`DeepSeekClient`、可信 IPC 骨架与错误码。
- 依赖阶段二：`resolveCallContext()`、取消与排空模式、AI IPC 暂停机制。
- **风险：现有检索是整串 `LIKE` 子串匹配**。自然语言问题（如「ref 和 reactive 有什么区别」）作为整串不会命中任何手记。本阶段必须新增多词检索入口，不能把完整问题直接交给现有 `search` 并声称具备语义召回。
- 风险：关键词检索无法命中同义改写。首版的取舍是「命中不了就说没找到」，不编造答案。
- 风险：来源编号由模型给出，必须经本地映射与校验后才能展示；模型可能给出越界编号或编造来源。
- 风险：检索结果随知识库增长，必须有词数与候选数上限。

## 6. 对后续阶段的影响

周期总结（阶段四）将复用本阶段确立的两项能力：`AiService.resolveCallContext()` 与统一的取消、排空、恢复暂停模式。**图片参与判断**（`AiImageReader`）留到阶段四引入——周期总结的数据面是「一段时间内的全部手记」，逐条送图有明确上限；而问答是逐次输入触发，每次送图会让费用随输入频率增长。此取舍记录在决策 007。
