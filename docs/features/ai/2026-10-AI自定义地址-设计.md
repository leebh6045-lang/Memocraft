# AI 自定义地址设计

## 配置与存储

`AiConfiguration` 增加必填 `baseUrl: string`，默认常量 `DEFAULT_AI_BASE_URL` 为 `https://api.deepseek.com`。追加迁移 `008_ai_base_url.sql` 为 `ai_settings` 新增带官方默认值的 `base_url` 列，模式版本升至 8，不改已发布迁移。地址与模型在同一 SQLite 单行配置内分别更新，互不覆盖；随完整备份恢复，旧备份在副本迁移后补官方地址，密钥仍在独立凭据目录。

`domain/ai-endpoint.ts` 的纯函数 `normalizeAiBaseUrl` 供服务与存储共用；主进程/客户端通过 `validateAiBaseUrl` 转换校验错误，存储发现损坏字段报 `STORAGE`，不静默回官方。只接受字符串，空白字符串回默认；有效地址使用 URL 解析，要求显式 HTTP/HTTPS 与非空主机，拒绝内部空白、控制字符、认证信息、查询参数、片段及超 2048 字符。不回显原始非法地址。保留子路径与端口，移除末尾斜线和完整地址的 `/chat/completions` 后缀，统一存为 Base URL；URL 编码后的入库值同样检查长度。

## 调用链

`ai.saveBaseUrl` → preload 新白名单通道 → `AiService.saveBaseUrl` → 存储线程 `saveAiBaseUrl` → `AiSettingsStore.saveBaseUrl`。沿用配置串行队列、写入追踪、错误归一化及关闭/恢复排空。`loadSettings` 和保存模型应答都返回当前地址。

`resolveCallContext` 返回 `AiCallContext { model, apiKey, baseUrl }` 快照；测试连接、建议、问答与周期总结把同一快照传给 `DeepSeekClient.complete`。客户端再次校验地址并拼接 `/chat/completions`，没有共享可变目的地址；既有请求不会因之后保存配置而改投。禁止自动跟随重定向，防止凭据或手记被转送到未保存的目的地。超时、取消、输出格式及无自动重试的语义保持。

## 设置页

在模型与密钥之间增加 API 地址（Base URL）输入框，预填已保存值；说明默认官方及 `/v1` 子路径，提供「保存地址」「恢复官方」。采用独立地址草稿，编辑清除本页测试结果，保存期间锁定配置，成功归一化回填，失败保留草稿与原配置。空地址保存也回默认。

地址有未保存改动时禁用测试连接并提示先保存或恢复；测试期间输入框和保存按钮禁用。保存模型不覆盖未提交的地址草稿，普通备份/导出后重读相同地址也保留草稿；知识库恢复实际改变存储地址后同步刷新地址与模型。界面说明所需文字和图片会发送到已保存的服务地址，避免自定义地址后仍声称只发往官方。

## 验证与兼容

覆盖 URL 归一化/非法输入、保存失败/重启、7→8 升级、旧版备份补默认及完整恢复、三个业务服务与连接测试实际使用自定义地址、修改取消旧测试、延迟写入排空、未保存不能测试、界面深浅主题/最小窗口。使用临时数据、测试凭据与 HTTP 替身；真实中转服务的协议兼容性另由用户配置后测试。

模式 8 不能由只支持模式 7 的旧应用打开；本次预览使用独立知识库和应用配置，不替换已安装应用，也不打开日常数据库。
