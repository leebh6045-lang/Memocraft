# AI 阶段三交付记录：搜索问答

> 实现已完成，类型、单元、SQLite、构建和最终桌面应用包验收均已通过。真实 DeepSeek 问答质量尚未验证，不将替身 HTTP 成功视为真实供应商验收；因此本记录和任务书仍保持 `in-progress`。

## 1. 已实现行为

- 在既有全局搜索面板的结果列表上方提供 AI 摘要，不新开页面或新增导航入口。问句去首尾空白后满 4 字符触发，600 ms 防抖；原有四类搜索仍独立采用 120 ms 防抖。
- 每次打开面板只读一次配置，未配置密钥时不调度问答、不闪现加载行。配置读取失败仍通过问答入口呈现明确错误；其余搜索照常工作。
- 只检索当前有效手记的标题、标签和正文，不含草稿、回收站、归纳、事务与动态。最多 8 个关键词，每词最多 20 条排序候选，合并后取前 8 条命中手记；总命中数独立统计完整并集。
- 标题、标签、正文按 3 / 2 / 1 加权，命中词数优先，再按权重、更新时间和 ID 稳定排序。摘录选覆盖最多关键词的最短命中窗口，再补上下文；正文最多 300 字符，两端可附省略号。只有标题或标签命中时取正文开头。
- 本地无命中时直接返回无记录状态，不调用 DeepSeek、不产生模型调用费用。
- 回答在原面板中收起或展开，收起仅用 CSS 单行省略。展开显示完整回答及来源；来源编号由主进程映射成真实手记 ID，标题由本地回填。合法来源点击后打开手记详情并关闭搜索面板。
- 非 JSON、缺字段、类型错误或空回答整份拒绝；超长回答截取前 400 字符并附省略号。重复、负数、零和越界来源编号丢弃；全部越界仍展示回答，隐藏来源区。模型文字以纯文本显示，不执行 HTML。
- 成功与无命中结果按 trimmed 问句缓存，当前面板最多 20 条；普通同词重查不重复计费，显式重试绕过缓存。面板关闭、手记集合或版本变化、编辑、切页、恢复、卸载均清理现场。
- 新问题取消旧问题，主进程等旧 flight 结算后接替，全部等待链均纳入排空。迟到成功或错误不能覆盖新现场。窗口关闭和知识库恢复同时暂停并排空问答、建议、配置三个服务，取消 IPC 在暂停期间仍可用。

## 2. 关键变更与兼容

新增 `domain/note-search.ts`、`storage/note-search-store.ts`、`main/ai-ask-service.ts`、`renderer/src/composables/useAiAsk.ts` 和 `components/AiAnswerRow.vue`。共享契约、输入校验、存储线程分发、可信 IPC、preload、断开桥接、搜索面板和 App 同步接线。

实现时核对了设计示意的三个遗漏：命中手记类型补齐分类；来源跳转改用实际会关闭面板的 `openSearchNote()`；缓存失效同时监听 `notes` 集合与版本，以覆盖不提高版本号的删除重读。细节记录在设计第 11 节。

不新增数据库迁移或运行时依赖，`SCHEMA_VERSION` 保持 6。问答只读，不持久化结果、不进入备份、导出或检索，不修改原 `SearchStore.search()` 的行为。

## 4. 已知限制与手动验收

- 当前检索为关键词匹配，不具备同义词或语义召回能力。没有命中时提示无记录，不能据此断言知识库从未记录相关概念。
- 本阶段问答只依据文字，不发送图片，也不做多轮对话或流式输出。图片与跨手记预算留到周期总结阶段统一设计。
- 来源映射保证引用 ID 与标题来自本次候选，不能保证模型概括正确；所有来源都越界时按设计保留回答，来源区为空。
- 尚未使用真实 DeepSeek 额度验证回答质量、实际延迟和同义改写命中体验。用户在设置页使用自己的有效密钥，用真实手记提问，检查回答是否忠于摘录、来源是否正确；不把密钥写入报告。
- 只验证 macOS arm64，未验证 Windows。

阶段二已依据用户「手动测试都正常」的反馈标为已交付；本次阶段三保持 `in-progress`，等待实际供应商手动验收结论。

## 5. 二次核验与优化（2026-10-11）

- **Prompt 编码说明缺失：确认。** 保留标题和问句的 `JSON.stringify()` 编码，在设计 3.3 节同步实际带引号格式、用途及非安全边界说明，并补代码注释。新增特殊字符用例，验证引号、反斜线、换行不会生成额外来源行，本地来源仍回填原始标题；真实供应商引用质量仍属于手动验收项。
- **`askVisible` 冗余：确认。** 全局搜索发现只有该 composable 和测试引用，生产界面直接使用 `phase`。删除接口、computed 和返回值，测试改为检查实际状态与界面隐藏行为。
- **检索词上限疑问：已核验，无缺失。** `validateRetrievalTerms()` 已完整校验载荷形状、原始最多 8 个词、每词原始最多 200 字符及非空白，检查后才 trim、去重。既有真实 SQLite 集成测试覆盖非法载荷、8／9 词、200／201 字符、重复词、通配符转义、候选截断与完整 `total`。本轮进一步确认非法载荷不进入 `NoteSearchStore.retrieve()`，并增加 null 词组与首尾空白不能绕过原始长度上限的案例。

本轮实际检查：5 个相关测试文件 **103 项通过**，Vue／TypeScript 类型检查、全仓 ESLint、定向 Prettier 和 Electron 构建均通过。第 3 节的 572 项全量及 17 项最终包桌面验证是此前交付证据；本轮没有重跑全量或桌面测试，也未消耗真实供应商额度。
