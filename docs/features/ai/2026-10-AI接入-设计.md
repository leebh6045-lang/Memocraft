# AI 阶段一设计：DeepSeek 接入

> 状态：已交付。2026-10-10 用户确认已手动测试，连接成功；具体逐模型测试详情未补录。阶段二已按 [归纳建议任务书](2026-10-AI归纳建议-任务书.md) 与 [设计](2026-10-AI归纳建议-设计.md) 开始实现。

## 1. 已确定的选择

采用 DeepSeek Chat Completions 接口，默认模型 Flash，两个模型共用同一密钥。模型选项与请求标识集中定义，不接受任意厂商或模型。2026-10-12 起允许在设置填写 Base URL，默认官方 `https://api.deepseek.com`；当前地址规则、迁移与验证见 [自定义地址设计](2026-10-AI自定义地址-设计.md)。

| 显示名称            | 请求 model        |
| ------------------- | ----------------- |
| DeepSeek V4.1 Flash | `deepseek-flash`  |
| DeepSeek V4 Pro     | `deepseek-v4-pro` |

官方依据：[首次调用](https://api-docs.deepseek.com/)、[模型与价格](https://api-docs.deepseek.com/zh-cn/quick_start/pricing)。

2026-10-10 对外部评估进行重新核验：官方首次调用页明确列出 `deepseek-flash`、`deepseek-v4-pro`，模型价格页对应版本为 DeepSeek-V4.1-Flash / DeepSeek-V4-Pro-0813。当前接入不改成旧的 `deepseek-chat` / `deepseek-reasoner` 名称，也不改写已经用于版本 6 数据库的 `006` 迁移。

[官方思考模式文档](https://api-docs.deepseek.com/zh-cn/guides/thinking_mode) 使用 `thinking.type = enabled / disabled` 控制思考开关，两个已支持模型都支持此参数且默认开启思考。客户端显式关闭思考是当前短文本调用的选择，参数并非 R1 专属；未来接入能力不同的模型时再制定对应参数，首轮不预建无用分支。

## 2. 职责与调用链

```text
SettingsPage → AiSettingsPanel → preload.ai → 可信主进程 IPC → AiService
                                                        ├→ StoreClient → 存储线程 → AiSettingsStore → SQLite
                                                        ├→ AiCredentialStore → safeStorage 加密密钥文件
                                                        └→ DeepSeekClient → Electron 网络接口 → DeepSeek
```

- `shared/ai.ts`：模型常量与跨进程契约，无运行时副作用。
- `storage/ai-settings-store.ts`：模型配置，与其他存储共用 worker 唯一连接。
- `main/ai-credentials.ts`：受控密钥文件访问；系统加密接口由装配传入，测试使用替身。
- `services/deepseek-client.ts`：HTTP 请求、响应校验与安全错误转换，不依赖 Electron。
- `main/ai-service.ts`：协调配置、密钥与测试生命周期，不另开数据库。
- `main/ipc/ai.ts`：校验来源、白名单方法、释放处理器。
- `renderer/.../AiSettingsPanel.vue`：独立 AI 编辑现场，与数据备份的加载/失败状态分开。

复用 Electron 内置网络能力以遵循系统代理；不添加第三方 SDK。网络请求在取得配置与密钥之后进行，不持有 SQLite 事务。

## 3. 存储与兼容

新增 `006_ai_settings.sql`：`ai_settings` 单行表，厂商固定 `deepseek`，模型仅允许两个已支持值。版本从 5 升至 6，默认 Flash。配置进入知识库 SQLite，备份/恢复会携带模型选择；恢复旧备份迁移后补默认行。

密钥保存为 `<userData>/credentials/deepseek.enc`；开发环境使用 `<userData>/development/credentials/deepseek.enc`。AI 桌面测试通过 `MEMOCRAFT_DATA_DIR` 与 `MEMOCRAFT_USER_DATA_DIR` 将知识库和 userData 设为隔离根目录中的兄弟目录；现有不涉及凭据的测试可继续使用原入口。密钥目录位于知识库 `data` 目录之外，不随知识库备份、恢复或 Markdown 导出迁移。

保存时先加密，再将密文写入权限为 `0600` 的临时文件，成功后原子改名替换；失败保留旧密钥。缺少文件表示未配置。拒绝系统加密不可用及 Linux `basic_text` 后端，不以明文替代。解密失败明确要求重新保存密钥；不删除原文件。密钥仅在主进程使用，读取状态不会回传密钥。

模型与密钥分开提交：选择模型自动保存，密钥通过「保存密钥」提交。这样无需跨 SQLite 与文件系统实现伪事务。测试仅使用已保存配置；输入了新密钥而尚未保存时，页面禁用测试并引导保存。

## 4. 跨进程契约

所有调用返回项目已有的 `Result<T>`：

- `ai.loadSettings()`：返回厂商、模型、是否已有密钥、系统加密是否可用。
- `ai.saveModel(model)`：持久化模型，返回保存的配置。
- `ai.saveBaseUrl(baseUrl)`：持久化规范化服务地址，返回保存的配置；`loadSettings` 和 `saveModel` 同时返回当前地址。
- `ai.saveKey(key)`：保存加密密钥，返回空成功结果；不返回密钥。
- `ai.clearKey()`：幂等删除本机密钥，返回空成功结果。
- `ai.testConnection(requestId)`：使用已保存配置测试，返回模型、验证时间与耗时。
- `ai.cancelTest(requestId)`：仅取消匹配请求，避免迟到的旧页面取消新测试。

主进程再次校验模型、密钥长度/空白、请求 ID。密钥必须为无内部空白的非空字符串，最多 512 字符，不假设固定厂商前缀。新 AI 错误码表达认证、余额、限流、网络、超时、取消、响应异常和密钥保护问题；不把未知 AI 异常归为本地笔记保存失败。

## 5. 测试请求与失败路径

POST 已保存的 Base URL 加 `/chat/completions`（默认 `https://api.deepseek.com/chat/completions`），Bearer 认证；固定文字 `Reply with OK.`，`thinking.type = disabled`，`stream = false`，小输出上限。成功必须得到有效响应结构与非空正文；仅连通服务或 HTTP 200 不算成功。返回页面只含测试元数据，不展示供应商原始错误正文。禁止自动跟随 HTTP 重定向，避免将密钥与手记转送到未保存地址。

请求有 30 秒总超时（包含读响应），通过 AbortController 取消；不自动重试。401/403 提示检查密钥或权限，402 提示充值余额，429 提示稍后再试，5xx 提示厂商暂时不可用；网络、超时、取消和响应格式异常分别表达。禁止记录 Authorization、密钥、原始请求/应答或知识正文。

请求格式错误（400）、参数错误（422）与模型或服务接口不存在（404）返回不同的安全提示，保留 HTTP 状态码并引导更新应用或反馈问题，避免将程序构造请求的错误归咎于用户选择。其他未分类 HTTP 错误同样保留状态码，不回传供应商原始正文。错误分类依据 [官方错误码](https://api-docs.deepseek.com/zh-cn/quick_start/error_codes)。

每个主进程同时最多一个连接测试。模型切换、保存/清除密钥、知识库恢复、窗口关闭时终止进行中的测试；配置读写按服务队列执行。恢复与关闭先等待已提交的独立凭据写入结束；在途写入失败时停止恢复或关闭，保留窗口与输入，再允许用户重试。测试先占用活动请求槽，再取得快照，防止准备期间重复调用。页面离开时取消自己的请求，并通过生命周期标识忽略迟到响应。恢复完成后 AI 区块重载模型配置，清除旧测试结果，保留未提交的密钥输入。成功结果仅在本次页面及当前配置下展示，重启后需重新测试；「已配置」不代表仍可调用。

## 6. 交互与隐私

AI 区块位于外观与数据之间。厂商固定显示，模型为下拉选择，API 地址可填写并保存或恢复官方，密钥为密码输入框。加载、保存、清除、测试均有反馈与重复操作限制；清除密钥保留当前模型与地址。测试期间可取消，页面其他本地功能保持可用。地址未保存时不测试，失败保留输入；完整交互规则见 [自定义地址设计](2026-10-AI自定义地址-设计.md)。

密钥保存反馈靠近操作位置：提交中按钮显示「保存中…」，只有收到保存成功应答才清空输入，输入框旁显示带勾选的绿色「密钥已保存」确认卡片，说明输入清空是为了保护密钥，同时通过现有全局提示条通知用户。API 密钥标签旁以带勾选的绿色状态标识显示「已配置」。确认卡片保留到用户重新输入、再次保存、清除或离开页面；模型切换、连接测试及配置重读不应擦掉与密钥无关的保存回执。配置重读发现密钥已不存在时清除回执。保存失败保留输入，不展示成功回执或成功提示条；密钥保存成功与连接测试成功仍是独立事实。

说明固定测试文本会产生少量费用、不会发送个人笔记；另说明使用 AI 功能会把所需文字与图片发送到已保存的服务地址。系统加密或 AI 配置错误只影响 AI 区块。未注入 preload 的浏览器提供明确不可用结果。

## 7. 验证方案与后续边界

- 客户端：两个模型、请求参数、非空生成、认证/余额/限流/服务故障、非法 JSON/空回答、网络、超时、取消、无自动重试。
- 密钥：真实临时文件的保存/更换/清除、重建实例读取、磁盘无明文、加密不可用/解密失败、替换失败保留旧值。
- SQLite：版本 5 升级到 6，原记录保留，默认/修改模型持久化与约束，备份恢复不影响密钥目录。
- 服务与界面：未配置、保存失败保留输入、模型保存失败恢复、重复测试、切页取消、无旧响应覆盖。
- Electron：真实 safeStorage、preload/IPC、设置操作、重启、模拟网络应答的桌面链路；真实 DeepSeek 调用另以有效密钥验证两个模型。

后续阶段沿用该调用基础，分别维护任务书和设计；阶段二文档已建立。归纳建议要校验候选归纳；问答须解决当前 LIKE 检索与 UUID 引用；周期总结须明确日期范围、刷新参数、生成时间及数据库事实统计。此阶段不预建尚未使用的三个业务接口。
