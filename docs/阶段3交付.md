# V2 阶段 3 交付 · 全对象搜索 · 2026-09-23

## 本轮成果

按 [V2 实施规划](V2实施规划.md) 第 4 节完成阶段 3：搜索从「只查手记」扩展为覆盖四类对象，并让浮层按类型分组、显示上下文、高亮命中，可从结果直接打开对应界面。

- **搜索范围**：手记（标题／正文／标签）、归纳（标题／说明）、事务（标题／说明／当前概况）、动态（描述／正文／标签）。
- **可见性**：草稿从不参与；已删除的手记、归纳、事务不参与；动态还要求所属事务未删除。**归档事务照常可检索**——归档只影响默认列表。
- **结果上限**：每类最多 20 条、总数最多 50 条，被截断时明确提示补充关键词。
- **空查询**：给出每类最近更新的 5 条，分组名写明「最近手记」「最近归纳」「最近事务」「最近动态」，不使用凭空的「最近访问」。
- **打开方式**：手记进抽屉、归纳进归纳详情、事务进事务详情、动态定位到所属事务并短暂高亮那一条。

## 关键文件

- `src/storage/search-store.ts`：一次查询覆盖四张表；LIKE 通配符转义、命中位置的上下文摘要、按类型分组与截断规则都在这里。
- `src/domain/search.ts`：`SearchHit`／`SearchResult` 与类型标签、上限常量。
- `src/renderer/src/highlight.ts`：先转义 HTML 再插入 `<mark>`，用于结果主行的高亮。
- `src/renderer/src/components/SearchPalette.vue`：分组结果、类型列与上下文列、键盘导航、按类型打开。
- `tests/integration/search-scale.test.ts`：真实规模下的耗时测量，作为「是否需要全文索引」的依据。

## 真实数据量测量（是否引入索引的依据）

`tests/integration/search-scale.test.ts` 用真实 SQLite 灌入 **2000 条手记、200 个归纳、100 个事务、3000 条动态**（合计 5300 行）后实测：

| 查询                       | 耗时   | 命中  |
| -------------------------- | ------ | ----- |
| 罕见关键词                 | 1.3 ms | 8 条  |
| 跨四类的常见词（触发截断） | 1.6 ms | 50 条 |
| 单类型常见词               | 1.3 ms | 20 条 |
| 空查询（每类最近 5 条）    | 1.1 ms | 20 条 |

结论：**当前规模下不需要全文索引或分词**，首版保持参数化子串匹配。该用例同时保留了 400 ms 的宽松上限，只拦截数量级退化；数据量显著增长或出现可感知延迟时，按 [V2 架构决定](decisions/002-V2架构决定.md) 的重新评估条件再测量一次。

## 期间修正的实际缺陷

1. **跳转意图被模块导航重置覆盖**（真实竞态）：打开意图的信号在 `navigate()` 之前发出，它的 watcher 先执行，随后导航重置把页面推回列表；从搜索结果打开归档事务时又因为默认列表不含归档项而落空。现在跳转统一为「先导航、后发意图」，目标不在当前筛选内时自动切到已归档再定位。
2. **旧的单表搜索与新的全对象搜索并存**会形成两份实现：已移除 `NoteStore.search` 与 `NoteSearchResult`，转义、大小写、上限、空查询等行为全部由新用例覆盖，没有丢失既有断言。
3. **运行时冒烟脚本仍在断言旧结构**（`scripts/runtime-smoke.mjs` 读 `search().notes`）：通道返回结构改变后由 `pnpm check:full` 拦下，已改为断言 `hits` 与 `hasMore`。这条正是门禁存在的意义——只跑单元测试不会发现它。

## 与规划的差异

- **检索入口只有一条通道**：原来的 `notes:search` 直接升级为全对象搜索，没有并行保留旧通道，避免两套语义。
- **结果行保留了两行主行**（标题 + 命中摘要），在基准的「类型列 + 标题 + 上下文列」之上多给一行摘要；主行已包含命中时不重复展示摘要。
- **动态结果不带独立页面**：按规划打开动态即定位到所属事务的时间线，不新增动态详情页。

## 剩余限制

- 搜索仍是子串匹配：分词、拼音、同义词与语义搜索后置；中文按连续子串命中，不做词边界处理。
- 结果不按相关度排序：同类内按最近更新倒序，跨类按手记、归纳、事务、动态的固定顺序分组。
- 回收站内容默认不参与（阶段 4 落地回收站后再评估是否需要「含回收站」的开关）。
- 平台证据仍只有 macOS arm64；Windows 未构建、未验证。
