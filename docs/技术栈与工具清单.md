# Memocraft 工具与环境

> 当前开发规范。项目已进入首轮桌面实现；本文的完整 v1 目标不等于全部已完成。实际范围与验证见 [首轮交付](首轮交付.md)。
> 公开文档入口见 [项目说明](../项目说明.md)，提交范围见 [仓库内容政策](仓库内容政策.md)。

## 1. 已确定的技术方向

Memocraft（创忆工坊）是本地桌面个人知识库，采用 **Electron + Vue 3 + TypeScript**。
首版直接验证桌面使用流程；CLI 可在真实需求出现后增加，不是开发前置条件。

产品由四个模块组成，工具与工程结构应服务这些边界：

| 模块     | 工程实现需要支持的行为                                                   |
| -------- | ------------------------------------------------------------------------ |
| 首页     | 单条草稿画布，以及新建知识归纳、新建长期事务的入口                       |
| 随手记   | 保存和查找全部独立手记；按“收获、待办、完成、杂项”四个固定分类选择和筛选 |
| 知识归纳 | 组织手记，同一手记可以出现在多个归纳中                                   |
| 长期事务 | 按时间呈现动态，并关联可复用手记                                         |

首页草稿与已保存手记应区分；不额外建立独立“收件箱”模块。
手记默认分类为“收获”，待办做完改分类为“完成”，可改回“待办”；不另设待办开关或完成勾选。开发阶段的应用界面左下角显示“内测中”。
具体字段、保存动作和交互规则由需求规格说明书定义，本文不重复数据模型。

## 2. 工具选择

| 层次         | 选择                 | 用途与边界                                   |
| ------------ | -------------------- | -------------------------------------------- |
| 桌面运行时   | Electron             | 窗口、系统集成与打包后的实际运行环境         |
| 界面         | Vue 3                | 四模块界面与组件                             |
| 语言         | TypeScript           | 渲染端、preload、业务与存储代码              |
| 构建         | electron-vite + Vite | 管理 Electron 各进程入口与前端构建           |
| 包管理       | pnpm                 | 安装依赖并提交锁文件，保证可重复安装         |
| 类型检查     | TypeScript + vue-tsc | 检查 TS 与 Vue 单文件组件，启用严格模式      |
| 测试         | Vitest               | 业务、存储、迁移和备份恢复的自动化验证       |
| 静态检查     | ESLint               | 代码检查与跨层导入限制                       |
| 格式化       | Prettier             | 统一文档与代码格式                           |
| 结构化存储   | SQLite               | 唯一结构化主存储，驱动待验证后选定           |
| 代码历史     | Git                  | 管理源代码、配置、迁移和测试                 |
| 安装包       | electron-builder     | 作为打包工具候选，通过试打包后固定配置       |
| 桌面流程测试 | Playwright           | 需要时验证关键 Electron 操作，不替代实际使用 |

开发机 Node.js 只负责开发工具与脚本；版本应满足所选工具的官方兼容要求。
生产构建应产出 Electron 可执行的代码，不依赖“本机 Node 可以直接运行 TS”的假设。
依赖版本在初始化时查询官方支持范围、安装并验证后锁定，不依赖未经核验的版本号。

## 3. 进程与调用边界

```text
Vue 渲染进程
    ↓ 有限、明确的业务调用
preload 暴露的类型化 API
    ↓ IPC
主进程侧业务服务与存储调度
    ↓ 必要时交给 worker / utility process
SQLite 与附件目录
```

- 渲染进程不直接访问 `fs`、数据库或任意 Node API。
- 保持 `contextIsolation`，关闭渲染进程 `nodeIntegration`，采用适用的沙箱配置。
- preload 只暴露明确能力，不暴露通用执行 SQL、任意路径读写或完整 `ipcRenderer`。
- 主进程校验 IPC 来源与输入，再进入业务服务；TS 类型不能代替运行时校验。
- 业务服务返回结构化数据与错误，不依赖界面提示、终端输出或 `process.exit`。
- 数据库连接由受控存储层持有，写入统一排队；一项业务操作通过事务提交。
- 大量查询、导入导出、备份和附件处理不能长时间阻塞主进程。
- 同步 SQLite 驱动执行重任务时放入专门工作线程或进程，并保留串行写入约束。

复用业务代码依赖这些边界及可测试的接口，不能仅凭“不 import CLI”保证无修改迁移。

## 4. SQLite 与文件存储约定

SQLite 保存手记、首页草稿、归纳、事务、动态、标签、关系与必要元数据。
正文以 Markdown 文本存入数据库；正文格式与数据库存储方式互不排斥。
附件文件放在独立目录中，数据库记录相对于数据根目录的路径，不保存机器绝对路径。
附件上传界面可以后置，但完整备份与恢复必须覆盖已经存在的附件。

关系由关联表表达，每种关系只有一个权威来源：

- 归纳与手记是多对多；不维护与关联表重复的 `homeId` 或持久化 `noteIds` 数组。
- `ThreadEntry` 必须属于一个 `Thread`，可引用手记；事务整体也可以引用手记。
- 查询结果可以包含手记 ID 列表，但该列表不是另一份可独立写入的关系数据。
- 删除、解除关联和恢复的行为按需求规格说明书执行，通过外键与事务落实。

存储层至少满足以下要求：

- 每个数据库连接显式执行并确认 `PRAGMA foreign_keys = ON`。
- SQL 值使用参数绑定；动态表名、排序字段等采用白名单，不能拼接用户输入。
- 对 IPC、导入文件和持久化数据边界执行运行时校验；校验库按成本选用。
- 唯一约束、外键和事务承担关系一致性，界面检查只是补充。
- 维护数据库模式版本和顺序迁移；不通过启动时静默重建数据库掩盖不兼容。
- 迁移前生成可恢复备份，失败后保留原数据并报告原因。
- 不将数据库与文件导出同时作为主存储，也不要求两边持续双写。

## 5. 驱动选择与兼容验证

先验证所选 Electron **内置的 Node.js** 是否提供并满足项目需要的 `node:sqlite`。
若不可用、接口能力不足或打包验证不通过，再评估 `better-sqlite3` 等驱动。
采用原生模块可能需要 `@electron/rebuild` 或打包工具配套重建，并非一律禁止。
驱动选定前不作“零依赖可用”“无需重编译”或“跨平台直接复用”的承诺。

| 必须记录的项目            | 通过标准                                          |
| ------------------------- | ------------------------------------------------- |
| Electron 与内嵌 Node 版本 | 从实际开发运行时和安装包运行时读取并记录          |
| SQLite 驱动与数据库版本   | 开发环境和安装包均能打开、读写同一测试库          |
| SQL 能力                  | 参数绑定、事务回滚、唯一约束与外键行为通过测试    |
| 备份接口                  | 能生成一致的数据库快照，并成功打开和恢复          |
| 工作线程或进程            | 所选驱动在最终执行位置正常加载，重任务不阻塞界面  |
| 原生模块 ABI              | 如使用原生模块，记录 Electron ABI、架构与重建方法 |
| macOS 安装包              | 在选定目标架构验证启动、读写、备份和恢复          |
| Windows 安装包            | 在选定目标架构验证启动、读写、备份和恢复          |

macOS 与 Windows 分别使用对应系统的构建环境验证；开发启动成功不等于安装包可用。
只声明实际验证过的系统与 CPU 架构，不将一次 arm64 测试扩大为所有平台支持。
签名、公证与分发方式按实际发布范围决定；在分发前验证目标机器的安装体验。

## 6. 首版备份、恢复与可读导出

完整备份、完整恢复与可读导出属于首版能力，应和数据库驱动一起验证。
Git 管理代码历史，不代替数据库或附件备份；同一磁盘上的副本也不能应对整盘故障。

完整备份应包含一致的数据库快照、附件、模式版本及校验清单。
备份过程中应协调数据库写入与附件变更，避免清单、数据库和附件来自不同状态。
优先使用经过验证的 SQLite 备份接口；替代方案需在写入停止后妥善关闭连接并复制。
启用 WAL 时，不能只复制仍在写入的主数据库文件来冒充完整备份。
备份先写入临时目标，完成完整性与附件校验后再标记成功；失败不得覆盖已有有效备份。

恢复先在临时位置验证备份完整性、模式兼容性和附件路径，再切换活动数据。
切换前暂停新编辑与新的数据变更，处理待保存请求并排空写入队列，再生成当前数据备份；保持暂停状态直到关闭连接并完成切换。保存或备份失败则停止恢复，恢复失败时应能回到切换前状态。
至少用包含归纳关联、事务动态、首页草稿和附件的样例做一次完整恢复验收。
备份位置应可由用户指定，以便保存到另一磁盘或已有备份系统覆盖的位置。

可读导出提供 Markdown 正文及必要的元数据、关联说明和附件，方便脱离应用阅读。
可读导出不默认承诺完整恢复能力；恢复应使用包含完整关系与模式信息的备份格式。
具体备份格式、保留策略与导出目录布局在实现前确定，并写入验收要求。

## 7. 验证与依赖管理原则

具体质量规则与修改流程以 [开发准则](开发准则.md) 为准。初始化时配置严格类型、ESLint 跨层导入限制、格式和测试脚本；接入 CI 后复用相同检查。首轮已配置本地检查入口，当前未接入 CI。

- 首先验证桌面最小链路：输入、保存、读取、重启后仍存在，然后逐步加入关系操作。
- 自动化测试覆盖业务规则、SQLite 真实约束、事务失败回滚、迁移与备份恢复。
- 关键界面流程需要实际操作验证，尤其是首页草稿保存、快速记录、检索和时间线。
- 必要时用故障注入验证写入与恢复失败；不能把所有崩溃测试都归为只能手测。
- 类型检查、测试和构建分别执行，不能用“构建成功”替代另外两项。
- 依赖以解决真实问题、维护成本和 Electron 兼容性为依据，不设固定数量上限。
- 新增依赖应说明用途并锁定版本；无需手写成熟库已经可靠解决的复杂行为。
- AI、云同步、语义搜索和插件系统在需求明确后另行评估，不进入当前主链路。

## 8. 开工前待决与记录

1. 查询并选定 Electron、工具链与开发机 Node 的兼容版本，提交锁文件。
2. 用最小打包样例选择 SQLite 驱动，记录两平台目标架构及验证结果。
3. 确定数据库工作线程或进程方案、串行写入入口及迁移机制。
4. 确定 Markdown 编辑与渲染方案；若允许 HTML 或外部链接，明确过滤和打开边界。
5. 确定备份格式、恢复切换方式、可读导出布局与用户数据目录。

项目依赖由 pnpm 安装，不需要手动部署 SQLite 服务。系统编译工具、Windows 验证环境和分发签名按实际需要提供；不把待验证项视为已完成。

## 9. 首轮实际选择

已固定 Electron 44.4.3、Vue 3.5.43、TypeScript 6.0.3、electron-vite 5.0.0、Vite 7.3.6、Vitest 5.0.1。Vite 版本受 electron-vite 的 peer 范围约束，TypeScript 版本同时满足类型检查与 TypeScript ESLint；不直接升级到不兼容主版本。完整版本以 pnpm-lock.yaml 为准。

采用 Electron 内置 `node:sqlite`，数据库由单个 worker 持有。Electron 44.4.3 内置 Node 24.21.0、SQLite 3.53.4 已在 macOS arm64 实际验证，开发 Node 为24.16.0。markdown-it 用于禁用 HTML/图片/链接的安全预览；SWC 包用于满足 electron-vite 暴露的类型依赖；eslint-config-prettier 协调格式规则。平台与打包证据见首轮交付，Windows 仍未验证。
