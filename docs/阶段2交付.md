# V2 阶段 2 交付 · 长期事务与动态 · 2026-09-23

## 本轮成果

按 [V2 实施规划](V2实施规划.md) 第 4 节完成阶段 2：长期事务与动态。事务是一件事的经历与决策，动态是它的时间线；动态可以独立写完整，也可以在同一流程里引用已有手记。

三块交付：

1. **2A 数据层**：迁移 `004_threads.sql`（`threads`、`thread_entries`、`entry_notes`、`thread_notes`、`entry_tags`）、领域类型与校验、`ThreadStore`，以及从渲染端到存储线程的完整契约。
2. **2B 事务界面**：事务列表（进行中／已归档筛选）、详情（标题与说明就地保存、**当前概况**独立编辑、动态输入区、时间线正倒序、归档与重新启用）、动态编辑对话框。
3. **2C 手记侧反查**：抽屉「被引用的位置」区分事务级与动态级两类引用，点引用直接跳到对应事务并定位到那条动态。

## 期间修正的实际缺陷

1. **`watch(..., { immediate: true })` 写在状态声明之前**（暂时性死区）。立即执行的回调在注册当刻同步运行，访问尚未初始化的 `let` 变量会抛错；Vue 捕获后只记录日志，页面照常渲染但「新建事务」表单永远不打开。已把声明与处理函数前置，并加注释说明原因。
2. **导航重置信号覆盖打开意图**。从抽屉点引用进入某条事务详情时，「回到列表」的重置先于「打开详情」执行，结果落在列表页。现在按导航先、意图后的顺序消费，与归纳页保持一致。
3. **时间线输入区重复渲染描述字段**：字段组同时用于输入区与编辑对话框，输入区已有描述输入框，导致同名字段出现两次。字段组支持隐藏描述，只在编辑对话框渲染。
4. **服务层校验比存储层宽松**（阶段 2 数据层发现）：空白动态描述与 `expectedRevision: 0` 被服务层放行，现在四条编辑路径统一收紧。
5. **列表页显示了写死的归档计数**：默认视图并不加载归档项，无法给出真实数字，已改为只显示筛选按钮，不留占位数字。

## 与规划的差异

- **删除入口仍未开放**。事务与动态的删除（软删除）、恢复与回收站页面按规划留在阶段 4；本轮完成的是删除的存储语义、恢复顺序与可见性规则的测试覆盖。
- **时间线排序切换会重新读取**，而不是在渲染端重排：排序规则（发生时间、创建时间、ID 三级）只有一处实现，界面不复制一套。
- **条目编辑用对话框**而不是原型里的就地编辑：字段较多（描述、发生时间、正文、标签），用同一套字段组承载，新建与编辑规则不会漂移。
