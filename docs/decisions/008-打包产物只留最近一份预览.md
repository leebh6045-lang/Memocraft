# 008：打包产物只留最近一份预览

## 问题

功能验收一直沿用「每轮单独打一个目录包，不覆盖旧包」的做法，交付文档里逐条记录了 `release/<功能>/mac-arm64/Memocraft.app` 的位置。每个目录包都是一份带完整 Electron 运行时的 `.app`（约 320MB），再加上 `release/mac-arm64` 的未封装目录包与历史版本的 dmg，磁盘上很快堆出数 GB 的同一应用副本；「系统设置 → 通用 → 储存空间 → 应用程序」会把它们作为重复项列出，用户无法分辨哪一份才是当前产物。

## 选择

新增 `scripts/clean-release.mjs`，由 `pnpm clean:release` 调用，并在 `package:dir`、`package:dmg`、`package:win` 打包前自动执行：

- 删除 `release/mac-arm64`：每次打包都会重新生成，旧目录包与当前 `out/` 本来就不匹配，不能再作为包内验证证据（见 [V2 实施规划](../V2实施规划.md)）。
- `release/<功能>/` 只保留最近修改的一份：那一份可能是正在使用的预览，同目录的手写启动器 `隔离预览.command` 不由打包生成，整目录删除会一并丢失。
- 删除 `release/` 根目录下文件名不含当前 `package.json` 版本号的 dmg/zip/exe/blockmap：旧版本安装包随时可重新构建。

脚本只处理 `release/` 下的已知产物形态；删除前逐个打印路径与体积，`--dry-run` 只报告不删除；每次删除前校验目标位于 `release/` 之内；删除失败如实报错并以非零码退出。`out/`、`.local/`、真实知识库与用户数据不在清理范围内。

功能预览包的标准命令（清理会先执行）：

```sh
pnpm run package:dir -c.directories.output=release/<功能>
```

参数必须直接跟在脚本名后。写成 `pnpm run package:dir -- -c...` 时 pnpm 会把 `--` 一并追加到命令末尾（`electron-builder --dir -- -c...`），electron-builder 从 `--` 起停止解析参数，覆盖不生效而静默退回 `release/mac-arm64`。

## 原因与代价

主要收益是不再让数 GB 的重复 `.app` 占盘，也不再顺手把上一轮的目录包当作本轮验证证据。

代价与边界：

- 历史功能预览包不再留档，复现旧预览必须重新打包；交付文档记录的是当时的路径，回看时要知道那些包已被清理。
- 清理发生在打包之前，因此构建失败时也不会保留上一轮的目录包。这是刻意的：旧包与当前 `out/` 不一致，留着只会让人误用。
- 「最近修改」是时间启发式：交替打两个功能的预览时，清理后可能短暂存在两份（上一份最近的 + 本次新建的），下一次清理收敛回一份。

## 重新评估条件

需要同时保留多份可比的安装包（对外分发回归、多版本升级测试）时，改为把产物输出到仓库外并保留固定份数，而不是放宽 `release/` 的清理规则。
