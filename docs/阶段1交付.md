## 期间修正的实际缺陷

1. **期望模式版本不能按迁移目录文件数推算**。原实现用「目录里有几个迁移文件」当期望版本，安装缺文件时会把用户库误报成「来自更新版本」，`NoteImageStore` 里的硬编码 `2` 更会在新增迁移后立刻让应用打不开。现在版本由 `src/storage/schema.ts` 显式声明，迁移文件数量不符时报出可定位的原因，备份清单记录的是**库自身的实际版本**。
2. **响应式数组不能跨进程传递**。收录时把 Vue 的响应式数组直接交给 IPC，结构化克隆失败（`An object could not be cloned`），界面只是静默无反应。已在跨进程边界转成普通数组，并由桌面流程覆盖。
3. **提示条没有数量上限**。连续操作会在几秒内堆出 7 条提示条铺满屏幕底部。现在同屏最多 3 条，超出丢弃最旧的一条。
4. **页面过渡期间的意图会丢失**。首页「新建归纳」在页面挂载完成前发出信号，表单不会打开。改为「挂载时消费一次意图 + 离开模块时重置」。
5. **归纳详情页点模块导航不会回到列表**，与基准不符；现在进入模块即回到列表。
6. **空正文提交缺少可见反馈**：补齐抖动与焦点回位。
7. **设置页的按钮式分段控件没有选中态**：补齐选中底块样式。

## 与规划的差异

- **只保留一个归纳读取通道**。规划文档里写过 `loadTopics` 与 `loadTopicsIndex` 两条；实现合并为一条，列表项直接带上收录手记 ID，避免同一事实有两份来源，`loadTopic` 详情通道也因此不再需要。
- **列表重排沿用既有机制**：行为与基准一致（320ms 平滑重排、新增项高亮），但使用 Vue 的列表过渡而不是照搬原型的 FLIP 实现。
- **首页「补充」区的关联入口尚未实现**。原型的补充区含「收录到归纳」与「关联事务」两行，前者需要扩展草稿载荷与提交事务，后者依赖阶段 2 的事务实体；本轮把该处文案改成说明真实入口（先保存手记，再到详情收录），列入阶段 2 一并设计。
- **设置页先落地「外观」与「关于」**，数据区（备份、恢复、导出）随阶段 5；归纳与手记的删除入口随阶段 4 的回收站一起开放，本轮只完成删除的存储语义与测试。
- 主题新增「跟随系统」一档，属用户确认的设计决定。
