## 2. 源码结构与职责

```text
src/
├── main/
│   ├── index.ts                      # Electron 启动、退出与服务装配入口
│   ├── window.ts                     # 窗口创建、安全配置与 IPC 来源校验
│   ├── close-window.ts               # 正常关闭握手：先保存编辑现场再关库
│   ├── image-protocol.ts             # 图片自定义协议：登记、来源粗筛与按 ID 取图
│   ├── store-client.ts               # 存储 worker 生命周期、请求超时与失败恢复
│   ├── ipc/                          # 有限业务 API 的处理器，含选图对话框
│   └── workers/                      # 存储线程入口，持有唯一数据库连接
├── preload/
│   └── index.ts                      # contextBridge 暴露明确业务 API
├── renderer/
│   ├── index.html                    # 渲染入口页面（含 CSP，图片协议在此放行）
│   └── src/
│       ├── main.ts                   # Vue 启动入口
│       ├── App.vue                   # 应用壳、模块切换、快捷键与关闭握手
│       ├── env.d.ts                  # window 桥接 API 类型声明
│       ├── shims-vue.d.ts            # 使普通 tsc 也能解析 .vue 导入
│       ├── api/bridge.ts             # 桥接替身：未注入 preload 时的明确失败
│       ├── pages/                    # 首页、随手记与尚未开放模块页
│       ├── components/               # 分类选择、卡片、抽屉、图集、搜索与图标
│       ├── composables/              # useLibrary 编辑现场、useNoteImages 图集、焦点
│       └── assets/                   # theme.css 设计令牌与过渡
├── domain/                           # 手记与图片类型、分类常量、图片签名规则
├── services/                         # 运行时请求校验与用例分发
├── storage/                          # 连接、迁移、SQL、图片文件与备份恢复
└── shared/
    ├── contracts.ts                  # IPC 请求、响应与桥接 API 类型
    └── errors.ts                     # 跨进程错误码与安全错误信息
```

首轮尚未建立 `renderer/src/api` 适配层：渲染端直接调用 preload 暴露的 `window.memocraft`。后续若出现需要复用的调用编排，再按实际职责加入，不预先创建空目录。

四个页面目录与用户看到的四模块对应；搜索和回收站按实际界面作为辅助页面或组件加入，不据此增加核心产品模块。一个功能内部先以少量文件实现，出现独立职责或实际复用后再拆分。

手记以 `category` 表达“收获、待办、完成、杂项”四个固定大分类，默认“收获”。编辑器和筛选器共用同一分类定义及顺序；待办做完通过改分类为“完成”实现，不维护另一份待办或完成状态。标签保持自由添加。

代码依赖约定：

- renderer 只调用 preload 暴露的业务 API，不导入 main、services、storage 或 Node 文件系统。
- preload 负责桥接，不编写 SQL 或复杂业务规则，不暴露通用 SQL/任意文件执行入口。
- main 负责应用生命周期、IPC 和装配；IPC 处理器调用 services，不在处理器中复制业务逻辑。
- services 协调业务规则和存储操作；有多项数据库变更的用例在同一事务内完成。
- domain 不依赖 Electron、Vue 或具体 SQLite 驱动；storage 不依赖界面组件。
- shared 只存真正跨进程共享的契约，不放数据库连接、运行时副作用或任意工具杂项。
- 工作线程或独立进程若用于存储，由其持有连接并执行对应服务/存储代码；不能跨进程传递数据库连接。具体入口在驱动验证后确定。

## 3. 迁移、资源与测试

迁移文件名格式为 `NNN_名称.sql`，三位数字从 `001` 连续编号（迁移管理器按此正则与顺序校验），当前为 `001_notes.sql`、`002_note_images.sql`、`003_topics.sql`、`004_threads.sql`。期望的模式版本由 `src/storage/schema.ts` 的常量显式声明，不由迁移目录的文件个数推算。已发布迁移保持不变，结构调整追加新版本；执行顺序和模式版本由迁移管理器记录。

迁移文件必须随安装包交付。使用 electron-builder 时，可将 migrations 配置为 extraResources，安装后从明确的资源路径读取；开发环境读取源码目录。不能依赖当前工作目录碰巧位于项目根目录，也不能只验证开发环境而漏掉安装包中的迁移文件。

resources 保存应用图标等静态资源；renderer/src/assets 保存由前端构建处理的资源；两者均不存放用户上传的附件。应用源码通常由打包工具封装，数据库与用户附件始终留在安装目录之外。

```text
tests/
├── unit/                             # 内容规则、分类与归纳校验、图片签名、时间与外观偏好
├── integration/                      # 真实临时 SQLite、图片、归纳、事务与动态、全对象搜索与规模测量、回收站、迁移、备份恢复与导出
├── e2e/                              # 桌面流程：记录链路、图片图集、知识归纳、长期事务、全对象搜索、回收站与数据管理
└── fixtures/                         # 用代码生成的最小图片样例，不含个人数据
```

需要桌面自动化时再添加 playwright.config.ts。测试生成的数据库使用系统临时目录或明确忽略的测试输出目录；不要访问真实用户知识库。SQLite 集成测试需使用与生产兼容的引擎能力，安装包另做驱动加载验证。

## 4. 运行时数据目录

用户数据与代码仓库分开。以 Electron 实际 `app.getPath('userData')` 为根路径；常见形态是 macOS 的 `~/Library/Application Support/<应用名>/`、Windows 的 `%APPDATA%/<应用名>/`，最终以运行时返回值为准，不硬编码机器路径。

```text
<userData>/
└── data/
    ├── memocraft.sqlite              # 正式业务数据、草稿、关系和元数据
    ├── memocraft.sqlite-wal          # 采用 WAL 时由 SQLite 管理
    ├── memocraft.sqlite-shm          # 采用 WAL 时由 SQLite 管理
    └── attachments/                  # 受管理附件，数据库保存相对路径
```

缓存和日志按需另设，不混入业务正文。完整备份写到用户选定的目的地，不写进 data/attachments，也不把本机副本当作异盘备份。测试库、用户库、安装资源与安装包分别管理。

## 5. 创建顺序与提交规则

1. 工程初始化时创建 package.json、锁文件、必要配置、应用入口、最小四模块导航及基础验证文件。
2. 实现持久化时加入 storage、初始迁移与真实数据库集成测试。
3. 开发对应功能时才加入 services、domain 规则、页面内组件和测试；不一次生成所有占位业务文件。
4. 打包与 CI 阶段补齐图标、打包配置和平台工作流。

代码、配置、锁文件、迁移、非敏感测试样例与文档提交 Git。node_modules、out、release、覆盖率、桌面测试报告、临时数据库、真实用户数据、签名证书和令牌不提交。初始化时建立实际 .gitignore 与格式化排除规则，本地参考资料不参与自动改写。

## 6. 首轮实际组织

`src/domain` 中 `note.ts`、`note-image.ts`、`topic.ts`、`thread.ts`、`search.ts`、`trash.ts`、`export.ts` 与 `library-data.ts` 加上 `src/shared/contracts.ts` 定义当前契约；`src/renderer/src/pages` 包含首页、随手记列表、知识归纳、长期事务、回收站与设置；`components` 包含分类选择、卡片、阅读流卡片、归纳连读、抽屉、图片图集、搜索、通用对话框、收录选择器、提示条与图标。`composables/useLibrary.ts` 协调首页草稿与抽屉两个独立编辑现场及保存次序，`useNoteImages.ts` 持有图集现场，`useNoteImageIndex.ts` 按手记 ID 批量缓存列表缩略图的图片摘要，`useTopics.ts` 持有归纳列表，`useThreads.ts` 持有事务列表、当前时间线与手记的反查结果，`useTrash.ts` 持有回收站列表与删除确认流程，`useToasts.ts` 与 `useModalLayer.ts` 分别负责提示条与模态层计数，`useModalFocus.ts` 负责分层浮层的焦点范围与恢复；`format-time.ts`、`theme.ts`、`view-preferences.ts`、`note-timeline.ts`、`scroll.ts`、`markdown.ts` 与 `highlight.ts` 是渲染端共用的纯函数与渲染配置模块（`scroll.ts` 说明主内容区才是滚动容器）。

`src/main/library-data.ts` 编排备份、恢复与导出的对话框与替换流程，`src/main/store-client.ts` 管理存储 worker 生命周期（按操作区分超时、支持重开），`close-window.ts` 负责关闭握手，`image-protocol.ts` 提供只认图片 ID 的取图协议，`ipc/register.ts` 校验来源并处理选图对话框与列表缩略图的批量取摘要。`src/storage` 中 `database.ts` 是连接、事务与迁移基础设施，`schema.ts` 声明当前模式版本，`note-store.ts` 管手记与草稿，`note-image-store.ts` 管图片文件与元数据（含列表缩略图用的批量摘要查询），`topic-store.ts` 管归纳与收录关系，`thread-store.ts` 管事务、动态与两类引用，`search-store.ts` 管覆盖四类对象的检索，`trash-store.ts` 管回收站列表、删除影响面与恢复，`backup.ts` 管备份目录包与恢复暂存，`recovery.ts` 管恢复前备份、中断标记与回滚，`export-store.ts` 管可读导出，`visibility.ts` 是跨实体可见性规则的唯一来源，`backup.ts` 管备份目录包与恢复。归纳、事务、附图与手记共用同一条连接，连接的所有权仍在 `NoteStore`。后续按真实职责增长拆分目录，不建立未接入的业务。
