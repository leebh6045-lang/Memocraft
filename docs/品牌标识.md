# Memocraft 品牌标识

本文件是品牌标识的当前方案与使用规则。界面颜色、圆角与尺寸令牌以
[界面与交互基准](界面与交互基准.md) 为准，本文不另立一套。

**当前状态：定稿为「折纸 M」（2026-09-24 用户确认），沿用已接入应用的原图标，
只按 macOS 标准尺寸收回并补上立体感。** 月亮方案未采用，保留在文末附录供追溯。

## 当前方案：折纸 M

四个相连的折纸面构成字母 M，右下方的书签切口象征保存与重访记忆。
M 是 Memo，折纸是 craft——名字本身就是图形。深蓝底在程序坞里辨识度高。

### 尺寸：严格按 macOS 图标网格

- **画布**：1024 × 1024。
- **底板**：苹果连续圆角 824 × 824，画布居中，四周留白 100。
- **投影**：只落在留白里，不越出画布。
- **M 包围盒**：x [256.28, 767.72]、y [284.69, 725.10]，水平居中。

旧版底板占满画布约 91%（464 / 512 的圆角矩形），在程序坞里比系统图标大一圈；
现在与系统应用一致占约 80%。M 按底板比例**等比**缩放（系数 824 / 464），
与底板的相对位置、比例与旧版完全相同；坐标直接算进路径，不套 `transform`。

底板是**苹果连续圆角**：圆角参数 r = 185.4，直边在距角 1.5287r（约 283）处开始弯，
每个角三段三次贝塞尔（系数取自对 iOS 连续圆角的逆向拟合）。
附录 3.1 那条样条超椭圆的角偏方（45° 处内缩约 31，连续圆角约 54），
在程序坞里比系统图标显得更大，已弃用。

### 立体感：五层

- **外投影**：底板同形六层，逐层下移 2→21、放大 0→2%、透明度 8%→2% 递减，叠出柔和扩散。
  不用高斯模糊（附录 6.3），也不用"位移 + 竖向渐变"——sips 下渲染成底部一条硬边灰条。
- **受光渐变**：底板 `#2e3b5e` → `#202A44`（原色居中）→ `#161d31`。
- **顶沿高光**：底板轮廓白色描边，被底板裁掉外半圈，只在上部渐隐可见。
- **下沿压暗**：底板下部 0 → 22% 的近黑渐变。
- **纸面投影**：M 外轮廓下移 6 / 15 / 26、透明度递减，让折纸浮在底板上。

### 颜色

- **底板（中段）**：`#202A44`。
- **左页、书签页**：`#E0CBA9`。
- **左折面 / 右折面**：`#FFF4E2` / `#F4E8D2`。
- **投影、压暗**：`#05070d` / `#0b1020`。

**不要把底板换成浅色。** 白底试过：奶油色纸面在白 → 暖灰底上对比度过低，
程序坞里 M 几乎看不出来，已否决。

### 文件

- `resources/brand/memocraft-app-icon.svg`：应用图标源文件（手工维护）。
- `resources/brand/memocraft-app-icon.png`：由上面 SVG 导出的 1024 位图，透明四角；打包与窗口图标都用它。
- `resources/brand/memocraft-mark.svg`：无底板标记，界面内使用。

`electron-builder.yml` 的 `icon:` 与 `src/main/window.ts` 都指向这个 PNG。
**改 SVG 后必须重新导出 PNG**，否则程序坞里看到的仍是旧图。
导出时注意附录第 6 节的渲染器差异（`clipPath` 与 `transform` 分层、不用 `mask`）。

# 附录 · 未采用方案：月亮（留作追溯）

以下为月亮方案的完整记录。其中第 3.1、6 节的 SVG 渲染经验对当前方案同样适用；
其余几何、字标与接入步骤均不再执行。

## 1. 方案

白色立体底板、黑色月牙居中（开口朝右上方）、淡金斜体书法字标居中压在最上层
（整条同色，不做反白）。

月亮取"记下来、慢慢积累"的安静意象；书法字标提供手工感，与月亮的几何形成对比。

## 2. 居中基准（重要）

"居中"在本方案里只有一个基准：**画布中心**。底板、月亮、字标三者都必须居中于它。

| 元素 | 判据                   | 实测偏差（1024 画布）              |
| ---- | ---------------------- | ---------------------------------- |
| 底板 | 包围盒（重心同值）     | (0.00, 0.00)                       |
| 月亮 | 包围盒与重心的加权偏置 | 包围盒 (+24, −24)／重心 (−89, +89) |
| 字标 | 字形包围盒             | (0.00, 0.00)                       |

- **字标不按重心判**。字重不均（`M` 粗、连笔细），实测重心是 (+19.68, −2.23)，
  但文字居中的通行判据是包围盒。要求重心也归零等于把字标整体右移，反而看着偏。
- **月亮是按比例偏置的**（`LUNE_BIAS`，当前 0.35）：0 = 按包围盒居中（四周留白均匀），
  1 = 按面积重心居中（视觉重量居中）。月牙的质量集中在弧的一侧，
  开口转到右上方 45° 后，两个口径最多相差 131px：

  | 偏置 | 四周留白（左/右/上/下） | 观感                     |
  | ---- | ----------------------- | ------------------------ |
  | 0    | 72 / 74 / 74 / 73       | 留白均匀，但墨迹偏左下   |
  | 0.35 | 117 / 69 / 69 / 118     | **采用**：墨迹被拉回中间 |
  | 1    | 会顶到右上角            | 不可用（包围盒超出底板） |

  全量按重心居中会溢出底板，所以做成连续参数取中间值。
  判据不是"某一个口径归零"，而是"两个口径都停在中间区域"——
  验收脚本按这个口径检查（包围盒偏差 ≤45、重心偏差 ≤120）。

**踩过的坑**：底板的垂直位置曾被设成 `(1024-824)/2 - 10`，为了多留一点投影空间。
代价是底板中心偏上 10px，于是"居中"出现了两套互相矛盾的基准——
按画布居中则字标看似偏下，按底板居中则整体偏上。**底板必须自身画布居中**，
投影用透明度而不是位移来腾空间。

**踩过的坑（更贵的一次）**：月牙的居中补偿量曾被写死成"外圆心右移 46"，
那是给旧月牙几何标定的。几何一换（见 4.3），同一个常数就失效，
实测墨迹重心偏右 141px，肉眼一眼可见。**补偿量必须算出来，不能拍一个数**——
现在由 `crescentCentroidX()` 解析求解，见 4.8。

**这两次踩坑合起来是一条规则**：居中口径和补偿量都跟着几何走，
换形状、换朝向之后必须重新实测，不能沿用上一版的结论（本文档自己就被这个坑纠正过两次）。

## 3. 立体白底

质感由四层叠出，不是单一阴影。四层都要有**实际可见作用**——
上一版有两层是空转（投影被裁在底板内又被不透明面色盖住、高光叠在纯白上面），
已经删掉：

1. **外投影** —— 三层同形位移（18 / 36 / 64px）+ 竖向渐变，落在底板之外。
   用渐变而不是高斯模糊的原因见 6.3。
2. **超椭圆底板** —— 苹果图标轮廓，824 / 1024，四周留白 100。
3. **垂直渐变** —— 顶 `#ffffff` → 中 `#fbfbfd` → 底 `#e8e8ef`，模拟从上受光。
4. **下沿压暗 + 细描边** —— 底板下沿内侧一条透明→5% 的渐变给出厚度；
   一圈 `stroke-opacity="0.08"` 的极淡暗边，避免白底在白背景上消失。

实测（1024 导出，x=250 一列）：y=150 是 (255,255,255)，y=900 是 (223,223,231)；
底板之下投影 alpha 从 924 行的 89 单调衰减到 988 行的 0，上方与两侧均为 0。

### 3.1 超椭圆必须用样条平滑

苹果图标不是普通圆角矩形，是超椭圆。**不能把采样点直接连成曲线**——
那样得到的是菱形，因为角点之间缺少切线信息。

做法：从苹果图标轮廓采集 20 个点，用 Catmull-Rom 样条平滑，
段 `P1→P2` 的两个控制点为 `P1 + (P2-P0)/6` 与 `P2 - (P3-P1)/6`。
点稀疏的地方也不会出现折线。

## 4. 月亮

**当前形状：月牙，开口朝右上方**（屏幕坐标 315°，即右上 45° 方向）。
两条弧、两个尖，没有其他元素。

参数按"观感量"给，不按弧半径给——用户反馈"开口太大、月牙太小"时，
调半径要反推半天，而张角与厚度是直接对应的：

| 元素         | 参数（1024 画布）                                 |
| ------------ | ------------------------------------------------- |
| 外弧张角     | 205°（月牙包得有多拢；越大开口越小）              |
| 最大厚度     | 0.44 × 外弧半径（月牙有多胖）                     |
| 形状基准半径 | 390（只做基准，整体大小由下面的缩放定）           |
| 开口方向     | 315°（0°=右、90°=下、270°=上）                    |
| 缩放         | 0.890（由包围盒目标 640 反解，纯等比）            |
| 居中偏置     | 0.35（0=包围盒居中，1=重心居中，见第 2 节）       |
| 两尖实测位置 | (856.79, 646.57) 与 (377.43, 167.21)，间距 677.91 |
| 包围盒       | x[217, 854] y[169, 806]，留白 117/69/69/118       |
| 与底板       | 底板 824，实测最小留白 69px                       |

**缩放只做等比变换**，所以"比例和弧度"与形态定稿时完全一致——
用户确认形态后要求"只缩小、不改形状"，等比缩放正是唯一保持形状不变的操作。

`(张角, 厚度)` 反解咬合圆的公式：半弦 `h = R·sin(W/2)`、弦位 `a = R·cos(W/2)`、
内圆心在外圆心 −x 方向 `d` 处且半径 `Rb = R − t + d`，
由"内弧必须过两个尖"解出 `d = t(t−2R) / (2(t − R(1−cos(W/2))))`。

### 4.1 旋转与缩放直接算进坐标，不套 `transform`

月牙先按"开口朝左"构造并做重心校正，再绕画布中心旋转 `开口方向 − 180°`、
等比缩放。两者都**算进路径坐标**，不写 `transform`：

1. 路径保持"两条弧 + 两个尖"，掩膜与解析都不必处理变换矩阵；
2. 绕中心旋转 + 等比缩放都不移动已校正到中心的重心；
3. 都是保向变换，两条 `A` 指令的 `sweep` 标志不用改（`large-arc` 由张角决定，见 4.4）。

### 4.2 尺寸与形态是两轮比出来的

**第一轮：形态。** 最初是张角 152.4°、厚度 0.267R 的细月牙，反馈"开口太大、月牙太小"。
把张角与厚度做成网格对比后定为 **205° / 0.44R**：开口明显收拢，
月牙面积从 77741px² 增到 139733px²（+80%）。

**第二轮：尺寸。** 尺寸用"包围盒目标边长"定（`LUNE_FIT`），
因为月牙转到对角线上以后长轴会顶住底板边缘——
竖直摆放时上下各留 33px 的尺寸，转到 45° 后两尖离边缘只剩 8px。

| 包围盒目标 | 留白（包围盒居中） | 结论                   |
| ---------- | ------------------ | ---------------------- |
| 651        | 87–88              | 细月牙时期，反馈"太小" |
| 740        | 42                 | 反馈"太大、太满"       |
| **640**    | 92（再偏置 0.35）  | **采用**：小一圈且居中 |

缩放由目标线性反解（绕中心等比缩放，包围盒边长同比变化），不用迭代。
圆盘模式仍在：`LUNE_MOON=disc`（半径 320，圆心即画布中心，天然居中）。

### 4.3 必须直接构造路径，不要用"外圆减内圆"

"外圆减内圆"的叠色法有两个坑，本项目都踩过：

1. **内圆与外圆尺寸接近时得到的是环**——月牙绕圆周走一整圈，上下各留一条细弧，
   看起来像两条月牙叠在一起；
2. **内圆偏移较大时会在另一侧再留一小段黑弧**——仍然是两条弧。

正确做法是**直接构造只有两条弧的路径**：

1. 求外圆与内圆的交点 `P1`、`P2`——这两个点就是月牙的两个尖；
2. 从 `P1` 沿外圆画弧到 `P2`；
3. 从 `P2` 沿内圆画弧回到 `P1`。

交点计算：设两圆半径 `R`、`Rb`，圆心距 `d`，
则交点在连心线上的投影 `a = (d² + R² − Rb²) / (2d)`，半弦长 `h = √(R² − a²)`。

**注意"圆心距"不等于"外圆心到画布中心的距离"。** 脚本里那个 `centerX`
只是水平平移量。上一版文档写成"开口朝右、外圆心右移 46"，与实际产物不符——
判方向不要看参数，看渲染出来的尖朝哪边。

### 4.4 弧心要用定义写，不要用"尖线偏移"近似（张角 >180° 会翻车）

两条弧的圆心**必须**按定义写：外圆心就是形状原点，内圆心在它 −x 方向 `d` 处。

踩过的坑：早先写成"外弧圆心 = 尖线 − √(R²−h²)"，因为 `√(R²−h²) = |a|`，
而张角 ≤180° 时弦位 `a ≥ 0`（尖在外圆心右侧），这个近似恰好成立。
**张角一超过 180°，`a` 变负、尖绕到圆心左侧，同一个式子就把弧心算到了错误的一侧**：
渲染出的月牙包围盒 887px，而脚本模型算成 600px，
于是自动缩放取错值、月牙直接溢出底板（实测外弧伸到画布外）。

**这类"只在某个参数区间成立"的近似，要连同成立条件一起写进注释**，
否则改一个参数就静默失效。自检办法：模型算出的包围盒必须与渲染出的掩膜包围盒对上，
验收脚本每次都会核对（当前模型 740 ↔ 实测 738，差值来自抗锯齿边缘）。

### 4.5 张角超过 180° 要改用优弧标志

外弧从尖到尖扫过 `W` 度：

- `W ≤ 180°` → `large-arc-flag=0`（劣弧）
- `W > 180°` → `large-arc-flag=1`（优弧）

内弧的跨度始终小于 180°（半弦必然小于内弧半径），保持 `0`。
写错标志不会报错，只会渲染出另一侧的弧——形状完全不同。

### 4.6 （月牙）两条弧必须朝相反方向弯（最容易错的一步）

在 SVG 里体现为两条 `A` 指令的 `sweep-flag` 相反（月牙为 `1` 与 `0`）。

**两条弧同向弯得到的是橄榄形（透镜形），不是月牙**——本项目也踩过这一步，
中间产出过一批"叶子"形状。

**自检方法**：把图案**单独渲染**（不加底板与文字），确认它只有两条弧、
两个尖。出现两条以上弧就是环，出现两个尖在上下端就是橄榄形。
生成脚本的 `LUNE_MEASURE=1` 会额外输出这种测量用的图案。

### 4.7 （月牙）内圆心垂直偏移必须为 0

垂直分量一旦非 0，月牙上下两侧会各多留一条细弧，同样读成两条月牙。
保持纯水平偏移，弧的走向才是干净的。

### 4.8 （月牙）基准摆放：按面积重心校正，且必须解析求解

月牙的质量集中在弧的一侧，**按圆心摆放并不等于按墨迹居中**。
这一步只负责把形状摆到"以重心为中心"，之后再按第 2 节决定是否改成包围盒居中。

做法：两条弧都用 `large-arc-flag=0`，渲染器取劣弧，因此两个圆心都在尖线左侧，
月牙 = 外圆在弦右侧的弓形 − 内圆在弦右侧的弓形。弓形面积 `A = R²·arccos(a/R) − a·h`、
重心距圆心 `(2/3)h³/A`，两式相减得到月牙重心，再反解平移量。

上一版把补偿量写死成常数，换几何后失效（见第 2 节）；现在由脚本算出。
**重心是可靠的基准摆放，但不是当前最终口径**——转到对角线后它与包围盒相差 171px，
当前取包围盒（见 4.2）；切回 `LUNE_ALIGN=ink` 时它就是居中口径。

**验证口径**：量月亮要用"图案轮廓掩膜"，不能只统计看得见的黑像素——
字标压在月亮上会遮掉一部分墨迹，且遮的是偏一侧的部分，
只数黑像素会把重心读偏（当前几何实测偏 20px，是假象）。

## 5. 字标

字体是 **Snell Roundhand Black**（macOS 系统自带的英文书法体）。

**字标已转成矢量路径，SVG 里不含任何 `<text>` 元素，不依赖本机字体。**
轮廓用 macOS CoreText 直接提取（见第 8 节），与系统实际排版的字形逐笔一致。

### 5.1 描边加粗到 1.6%

Snell 的字身极细，连笔画只有 1–2px。描边取**字标宽度的 1.6%**。
用描边而不是换更粗的字体，是因为描边等量加在所有笔画上，
书法原有的粗细对比（粗主干 + 细连笔）完整保留。

### 5.2 压在月亮上的笔画：对比度实测够用（旧结论已更正）

字标整条用同一个淡金 `#e8c95a`，一部分压在近黑月亮 `#141414` 上。
按 WCAG 相对亮度算：

| 组合                            | 对比度    |
| ------------------------------- | --------- |
| `#e8c95a` 压在月亮 `#141414` 上 | **11.35** |
| `#e8c95a` 在白底上              | 1.62      |

**也就是说字标压在月亮上反而比压在白底上更清楚。** 本文档早先写过
"压在月亮上对比度只有约 3.4、字母接近消失"——那个 3.4 是**白底**那一档的数字
被误用到月亮上，结论是错的，已更正。

**当前这一档低于本文档的标准**（白底 1.62 < 3.0），是刻意的风格取舍，见第 7 节。
字标 81% 的笔画落在白底上，所以白底那一档就是它的实际可读性；
压在近黑月盘上 11.35，非常充裕。
当前几何下压在月亮上的字标像素有 12861 个（月亮掩膜 104490 px 的 12%），
渲染出来是清楚的。

**唯一的真实代价**：书法笔画只有 3–8px 宽，细连笔压在整片黑上会显得更细，
视觉重量比在白底上轻一点。这是细笔画在任何深底上的通性，不是颜色选错。

**层序不是问题。** 用像素差验证过：字标确实绘制在月亮之上。
现在的验收脚本也用图案掩膜复核了这一点：掩膜内 104490 px 中
墨迹 91285、字标绿 12861、其他色仅 344，
若字标在下层，这 12861 px 应当是黑色墨迹。

试过并否决的三种处理：

| 处理                            | 结果                                           |
| ------------------------------- | ---------------------------------------------- |
| 换成同色系更亮一档（`#a9cdec`） | 可读（11.08），但一个字两种颜色，用户明确否决  |
| 转白                            | 月亮凹处也是白色，两者连成一片，月亮看着被掏空 |
| 缩小月亮                        | 可读，但用户要求月亮更大                       |

**当前取舍**：整条同色、月亮尺寸优先。若哪天仍要更强的可读性，
代价必然落在下面三者之一——月亮缩小、字标换色、或字标避开月亮。
`mark-moon.svg`（界面内使用）与图标同源，表现一致。

## 6. 三个必须避开的 SVG 写法

### 6.1 `clip-path` / `mask` 不能与 `transform` 同元素

```xml
<!-- 错误：两种渲染器结果不同 -->
<g transform="translate(0 22)" clip-path="url(#tile)">…</g>

<!-- 正确：裁切在外层，位移在内层 -->
<g clip-path="url(#tile)">
  <g transform="translate(0 22)">…</g>
</g>
```

`clipPath` 用 `clipPathUnits="userSpaceOnUse"` 时，裁切区域在元素变换**之前**还是
**之后**生效，各实现解释不一致：Chrome 按变换后解释、把内容切成碎片，
sips 按变换前解释、结果正常。同一份文件在"文件夹预览"里正常、浏览器里碎掉，
就是这个原因。

### 6.2 `mask` 在 sips 上不可靠

实测：`mask` 漏写 `maskUnits="userSpaceOnUse"` 会**静默失效**（不报错、直接不生效），
补上后本方案里仍不稳定。**一律改用 `clipPath`。**

### 6.3 滤镜输出被裁在对象包围盒内，模糊做不出"越出底板"的投影

`sips` 支持 `feGaussianBlur`（6.1 里"不支持滤镜"的旧结论是错的），
但它把滤镜结果裁在**对象包围盒**内，`filterUnits="userSpaceOnUse"` 放大的滤镜区域无效：

- 形状位移 +26、模糊 σ=26 时，投影在 y=950（= 形状自身包围盒下沿）**硬切为 0**；
- 用 `fill-opacity="0"` 的大矩形撑大包围盒也不生效，仍然硬切。

结论：想拿到"越出底板"的柔和投影，**不要用模糊**，改用
**同形位移 + 竖向渐变到透明**（`gradientUnits="userSpaceOnUse"`）。
生成脚本里是三层 `[18, 0.16] [36, 0.1] [64, 0.07]` 的叠加，
实测 alpha 从底板下沿的 89 单调衰减到 0，且上方、两侧都没有漏出。

### 6.4 渐变随元素一起被 `transform` 平移

SVG 规定渐变定义在引用它的元素的用户坐标系里，元素自身 `transform` 会连渐变一起平移
（sips 与 Chrome 行为一致）。所以"在设备坐标里写死 y=924 起渐变的投影"会被位移带走，
整层退化成一个**恒定 alpha 的硬边色块**——表现为投影是几级台阶而不是平滑衰减。
正确写法是在形状自身坐标里给区间：`y1 = 下沿 − 位移`，`y2 = 下沿`。

## 7. 颜色与尺寸

| 用途               | 色值                                      |
| ------------------ | ----------------------------------------- |
| 底板渐变           | `#ffffff` → `#fbfbfd` → `#e8e8ef`         |
| 月亮               | `#141414`                                 |
| 字标（整条同色）   | `#e8c95a` 淡金（白底 1.62／月盘上 11.35） |
| 投影 / 描边        | `#1a1a24`（冷调近黑）                     |
| ~~字标压在月亮上~~ | `#a9cdec` 已否决，产物中不再出现          |

字标选色的一般依据：书法是细笔画，比同色粗体更难读，因此按"大字"标准（≥3.0）要求，
且以**白底**那一档为准（笔画 81% 落在白底上）。淡蓝时期实测四档为
`#3b8fd4` 3.46、`#4a9fe0` 2.87、`#63b0e8` 2.36、`#7cc0ef` 1.97，取达标的上限。

**金色这一版是有意破例**。金色是高明度色，白底对比度天然偏低，实测：

| 金色候选  | 白底 | 月盘上 | 观感               |
| --------- | ---- | ------ | ------------------ |
| `#ffd700` | 1.40 | 13.13  | 最"金"，白底上发飘 |
| `#d4af37` | 2.10 | 8.76   | **采用**：金属金   |
| `#c9a227` | 2.42 | 7.62   | 深一档             |
| `#b8860b` | 3.25 | 5.66   | 达标，但偏古铜     |
| `#a67c00` | 3.82 | 4.83   | 更暗，接近棕       |

只有偏暗的金能过 3.0，而那就不是"金色"了。所以这一档由**风格优先**决定：
用户明确要金色，接受白底上可读性下降；`LUNE_WORD=#b8860b` 可随时切回达标档。

| 尺寸             | 表现                                   |
| ---------------- | -------------------------------------- |
| 1024 / 512 / 256 | 月亮与字标都清楚，底板质感完整         |
| 128              | 字标可读，月亮清楚                     |
| 64               | 字标退化为蓝色条带，圆盘仍完整         |
| 32               | 只剩圆盘与一条蓝带（圆盘比月牙更耐缩） |
| 16               | 只剩底板与月亮的色块                   |

结论：**带字标的应用图标最小 128px**；64px 及以下改用 `mark-moon.svg`（不带字标）。
圆盘在 32px 仍能读出"黑圆"，比同尺寸的月牙清楚——这是圆月的额外好处。

| 文件                                | 用途                                                               |
| ----------------------------------- | ------------------------------------------------------------------ |
| `app-icon.svg`                      | 应用图标：立体白底 + 圆月 + 字标                                   |
| `mark-moon.svg`                     | 界面内标记：无底板，只有月亮与字标                                 |
| `app-icon-on-dark.svg`              | 深色主题标记：同样无底板，月亮反白、字标换更亮的金 `#e8c95a`       |
| `assets/`                           | 位图：`app-icon-16…1024.png`、`mark-moon-512.png`、`app-icon.icns` |
| `assets/app-icon-1024-on-light.png` | 浅底展示图（合成到 `#f2f2f7`），只看立体观感，不参与打包           |

`app-icon-on-dark.svg` 曾经带白色底板 + `#f2f2f6` 月亮，实测月亮像素是 (253,253,253)
而底板是 (255,255,255)——**月亮实际不可见**。现在它不带底板，用在深色界面里。

全部 SVG 由脚本生成，不要手工编辑：改几何后重新运行生成脚本会覆盖。

**生成方式：**

- 几何与字标：`.local/planet/build-lune.mjs`
  - `LUNE_MOON=crescent|disc` 月亮形状（默认 `crescent` 月牙）
  - `LUNE_OPEN=<角度>` 月牙开口方向，屏幕坐标（默认 315 = 右上方）
  - `LUNE_WRAP=<角度>` 外弧张角，越大开口越小（默认 205，见 4.2/4.5）
  - `LUNE_THICK=<比值>` 最大厚度 / 外弧半径（默认 0.44）
  - `LUNE_FIT=<边长>` 旋转后包围盒目标边长，缩放由它反解（默认 640）
  - `LUNE_BIAS=0..1` 居中偏置（默认 0.35，见第 2 节）
  - `LUNE_WORD=#rrggbb` 字标颜色（默认 `#e8c95a` 淡金，见第 7 节）
  - `LUNE_S=<倍数>` 直接覆盖缩放（一般不用）
  - `LUNE_ALIGN=bbox|ink` 月牙居中基准（默认 `bbox`，见第 2 节）
  - `LUNE_R=<半径>` 圆盘模式的半径（默认 320）
  - `LUNE_OUT=<目录>` 输出到别处，用于对比候选
  - `LUNE_MEASURE=1` 额外输出只有月亮的 SVG，供居中自检
- 字形轮廓提取器：`.local/planet/glyph-path.swift`

两者都在本地原型目录（不提交）。要长期维护应移入 `scripts/` 并纳入检查。

**验收脚本**：`.local/planet/verify-lune.py`（同样在本地原型目录，用标准库自己解码 PNG，
本机没有 PIL/numpy）。它核对配色、三者居中、层序（用图案掩膜判定，不靠肉眼）、
以及四层立体效果是否真的渲染出来。改几何后应重跑：全部通过才算产物可用。

**字形提取器用法**：

```sh
swiftc -O -module-cache-path ./build-cache glyph-path.swift -o glyph-path
./glyph-path "Snell Roundhand" Bold "Memocraft" 1000 > word-bold.json
```

### 8.1 接入时注意：图标不要再叠系统遮罩

本方案的 `app-icon.svg` **已自带超椭圆底板、渐变与投影**。
macOS 打包时若再让系统套一层圆角遮罩，会出现双重圆角与双重阴影。

两种处理，二选一：

1. **交给系统**（推荐用于 dmg 内）：把底板四层去掉，只保留月亮与字标
   （即直接用 `app-icon-on-dark.svg` 那种无底板产物，颜色换成深墨），
   让 macOS 自己加圆角与质感；
2. **自己封**（推荐用于文档、站点、关于页）：保留当前带底板的版本。

当前产物是第 2 种。接入 dmg 前需按第 1 种另出一版，否则 Dock 里会看到两层边。

## 10. 不要这样做

- 不要拉伸或改变长宽比。
- 不要把底板单独位移——居中基准是画布中心（第 2 节）。
- 不要在超椭圆上用普通圆角矩形替代（会失去苹果图标的"涨"感）。
- 不要用 `mask`，一律用 `clipPath`（第 6.2 节）。
- 不要用 `feGaussianBlur` 做越出底板的外投影，它会被裁在包围盒内（第 6.3 节）。
- 不要把月亮的居中补偿写死成常数，换几何就失效（第 2、4.8 节）。
- 不要沿用上一版的居中口径：竖直月牙用重心、转到对角线后改用包围盒，
  两者差 171px（第 2、4.2 节）。
- 不要把月牙按竖直摆放的尺寸直接转到对角线上：缩放 1.0 时两尖离边缘只剩 8px（第 4.2 节）。
- 不要用非等比缩放改月牙大小：那会改变弧度与比例，形态定稿后只允许等比缩放（第 4 节）。
- 不要把 `LUNE_BIAS` 拉到 1：全量按重心居中会让包围盒顶出底板（第 2 节）。
- 不要用"尖线偏移 √(R²−h²)"算弧心，它只在张角 ≤180° 成立，>180° 会把月牙甩出底板（第 4.4 节）。
- 不要把 `large-arc-flag` 写死为 0：张角 >180° 必须用优弧，写错会静默渲染成另一侧的弧（第 4.5 节）。
- 不要在旋转后靠 `transform` 收尾：旋转与缩放直接算进路径坐标，掩膜与解析才不会被绕开（第 4.1 节）。
- 不要为了"更清新"继续调淡字标颜色：淡蓝时期的四档实测（3.46／2.87／2.36／1.97）就是那道边界。
- 不要指望在金色里找到"又亮又达标"的一档：金色族在白底上最好的也只有 1.4–2.4，这是结构性冲突（第 7 节）。
- 金色不要再往淡里推：`#ffeaa7`（白底 1.19）字标已经糊在白底上，`#e8c95a` 是仍看得见的边界（第 7 节）。
- 不要照抄本文档早先关于"压在月亮上对比度不足"的结论，那是误用白底数字（第 5.2 节）。
